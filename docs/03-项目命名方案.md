## 1. 命名约束

团队名 **AperturePrism**（光圈 + 棱镜）已经确立了一套完整的光学隐喻体系。项目名必须同时满足六个约束：

| # | 约束 | 理由 |
|---|---|---|
| C1 | **与团队名同源但不重复** | 团队名描述观测手段，项目名应描述观测目的，二者构成完整叙事 |
| C2 | **能表达第一原则（可证明性）** | 项目的灵魂是"让证据显现"，而非"生成结论" |
| C3 | **短、好读、CLI 友好** | 需要一个可当命令名的短形式（理想 ≤ 6 字符） |
| C4 | **未被主流安全项目占用** | 避免检索污染 |
| C5 | **国际化无障碍** | 中英文环境下均不产生负面歧义 |
| C6 | **经得起十年** | 不做"看起来像 2026 年"的时髦命名 |

## 4. 决策：Aletheia

### 4.1 选择的理由

**理由一：语义与第一原则完全同构，不是比喻而是定义。**

Aletheia（ἀλήθεια）在古希腊语中由 a-（否定前缀）与 lēthē（遮蔽、遗忘）构成，字面意思是"**不遮蔽**"。海德格尔在《存在与时间》中将其阐释为"去蔽"（Unverborgenheit）——**真理不是被"制造"出来的判断，而是被遮蔽之物自行显现的过程。**

这与项目核心机制精确对应：

| Aletheia 的哲学含义 | 项目的技术实现 |
|---|---|
| 真理不可被"生成"，只能被"显现" | 结论不可由模型声称，只能由证据支撑 |
| 遮蔽是默认状态 | 幻觉是默认状态，需要主动消除 |
| 去蔽需要正确的观测方式 | 需要棱镜分解 + 光圈控制 + 焦平面成像 |
| 显现是可验证的事件 | Confirmed 状态必须可独立复现 |

**其他候选都在描述"我们怎么做"（Focalis 说焦平面、Lattice 说图结构、Iris 说孔径）；Aletheia 描述的是"我们要达到什么"——这正是项目名应该承担的语义层级。**

**理由二：与团队名构成完整叙事。**

```
AperturePrism（团队）  ──▶  用什么观测：光圈 + 棱镜（控制进光量、分解维度）
Aletheia      （项目）  ──▶  为了什么：让被遮蔽的真相显现
```

一句话对外介绍："AperturePrism 团队做了一套叫 Aletheia 的系统 —— 名字取自希腊语的'去蔽'，因为我们相信渗透测试的结论不该由模型声称，而该由证据显现。"

**理由三：长期性最好。** 哲学词根不会随技术潮流贬值。C6 是六个约束中最容易被忽视但影响最久的——三年后看，"Focalis"会显得像 2026 年的产物，"Aletheia"不会。

### 4.2 已知代价与应对

| 代价 | 应对 |
|---|---|
| 8 字母，CLI 输入略长 | 官方短形式 **`aleth`**（5 字符）；包名 `aletheia`；命令 `aleth` |
| 非希腊语背景者不熟悉 | **把词源写进 README 第一段**——命名故事本身就是最好的项目简介 |
| 中文音译"阿勒忒亚"略拗口 | 中文语境下直接使用拉丁字母 Aletheia，不强制音译 |

### 4.3 保留的次选：Focalis

**若后续需要改名，唯一推荐的替代是 Focalis。** 它直指架构最核心的 L3 焦平面层，短、好拼、国际通用、零撞名。代价是语义层级较低（描述机制而非目的）。

**改名成本极低：** 本项目所有文档与代码中，项目名仅出现在文档标题、包名与 CLI 命令三处，一次全局替换即可完成。
