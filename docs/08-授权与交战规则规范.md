## 0. 本文档要解决的问题

**Aletheia 是一个自主渗透系统。它会在没有人类逐步确认的情况下执行攻击性动作。**

这带来一个不可回避的设计要求：**必须有一个机制，让"授权"成为系统运行的前置物理条件，而不是使用者需要自觉遵守的约定。**

参照调研中的反面案例：HexStrike AI 于 2026 年 8 月被报道用于自动化利用某 Citrix 漏洞。**开源 + 工具链 + 自主规划同时降低了专业红队门槛和滥用门槛。** 项目方有责任设置最低门槛。

本文档定义：

| # | 内容 |
|---|---|
| 1 | Authorization Anchor —— 无授权不启动的强制机制 |
| 2 | 授权凭证的结构化格式（可校验、可审计） |
| 3 | Scope 定义语法（目标、排除、动作、时间窗、速率） |
| 4 | ROE（交战规则）字段 |
| 5 | 越界判定与熔断语义 |
| 6 | 审计要求 |
| 7 | 合规声明模板 |
| 8 | 法律依据 |

## 1. Authorization Anchor（授权锚定）

### 1.1 强制机制

```
进程启动
   │
   ├─ 是否提供 --authorization <path> ？
   │       否 ──▶ 打印说明 + 退出码 3（拒绝启动）
   │
   ├─ 凭证文件是否存在、可读、结构合法？
   │       否 ──▶ 打印具体错误 + 退出码 3（拒绝启动）
   │
   ├─ 凭证是否在有效期内？（valid_from ≤ now ≤ valid_until）
   │       否 ──▶ 打印过期信息 + 退出码 3（拒绝启动）
   │
   ├─ 凭证是否完整（必填字段齐全 + 至少一个 include 目标）？
   │       否 ──▶ 打印缺失字段 + 退出码 3（拒绝启动）
   │
   └─ 全部通过
          ├─▶ 凭证内容哈希写入审计日志（哈希链首条）
          ├─▶ 凭证与本次会话绑定（session_id）
          └─▶ 服务启动
```

**三条硬约束：**

| # | 约束 | 说明 |
|---|---|---|
| **1** | **无凭证不启动** | 不是警告、不是降级、不是"仅侦察模式"。是**拒绝启动** |
| **2** | **校验发生在最早时机** | 在绑定端口、加载模型、初始化沙箱**之前**。不留"先跑起来再校验"的窗口 |
| **3** | **凭证与 scope 绑定且不可热改** | 运行期修改 scope 必须重新提交凭证并重启会话（见 §5.4） |

### 1.2 为什么不做"警告后继续"

调研记录的失败模式之一是"范围控制弱 → agent 触碰从未纳入演练的系统"。**"警告后继续"在实践中等同于"没有控制"** —— 因为用户在扫描开始后不会再读警告。

对齐项目的 P-4 原则：**失败即熔断，不降级。**

### 1.3 退出码约定

| 退出码 | 含义 |
|---|---|
| 0 | 正常退出 |
| 1 | 运行期错误 |
| 2 | 配置错误 |
| **3** | **授权校验失败（独立退出码，便于 CI 与监控识别）** |
| 4 | 范围越界熔断（见 §5.3） |

## 2. 授权凭证格式

**格式：YAML（人可读、可审阅、可版本控制）。文件名约定 `roe.yaml`。**

```yaml
version: 1

authorization:
  # —— 授权来源（必填）——
  granted_by: "广西某科技有限公司"              # 授权方名称
  granted_to: "AperturePrism 团队 / Binbim"     # 被授权方
  contact: "security@example.com"               # 授权方安全联系人（应急联络）

  # —— 凭证引用（至少提供一个）——
  ticket_id: "SEC-2026-0912"                    # 工单号
  document_hash: "sha256:7f3a1b2c..."           # 授权书文件哈希
  document_path: "./授权书-2026-09-24.pdf"       # 可选：原件路径（不入日志）

  # —— 有效期（必填）——
  valid_from:  "2026-09-24T00:00:00+08:00"
  valid_until: "2026-10-24T00:00:00+08:00"
```

**校验规则：**

| 字段 | 规则 |
|---|---|
| `granted_by` / `granted_to` / `contact` | 必填，非空 |
| `ticket_id` 或 `document_hash` | **至少一个**必填 |
| `valid_from` / `valid_until` | 必填，且 `valid_from < valid_until`，`valid_until - valid_from ≤ 90 天`（超长授权需说明理由） |
| 当前时间 | 必须落在有效期内 |

**隐私约束：** `document_path` 指向的原件**不进日志、不进上下文、不上传**；只记录其哈希。

**机器可校验定义：** 完整的 JSON Schema 见 [`schemas/roe.schema.json`](schemas/roe.schema.json)（JSON Schema Draft 2020-12）。Schema 只校验**结构与字面约束**；运行期语义 —— 排除项优先于包含项、默认拒绝、时间窗在**执行期**校验、`dos`/`destructive` 的硬编码保护 —— 由 Scope Kernel 实现，不在 Schema 表达范围内。

## 3. Scope 定义语法

```yaml
targets:
  include:
    - cidr: "10.40.23.0/24"
    - host: "app.example.com"
      ports: [80, 443, 8080]        # 可选：限定端口
    - url_prefix: "https://api.example.com/v2/"
  exclude:
    - cidr: "10.40.23.128/25"       # 生产数据库段 —— 明确排除
    - host: "pay.example.com"        # 支付系统 —— 禁止触碰
    - url_prefix: "https://app.example.com/admin/billing"
```

**匹配语义（优先级从高到低）：**

| 顺序 | 规则 | 说明 |
|---|---|---|
| 1 | `exclude` 命中 → **拒绝** | **排除项永远优先于包含项** —— 这是安全默认 |
| 2 | `include` 命中 → 进入后续检查（动作/时间/速率） | |
| 3 | 均未命中 → **拒绝** | **默认拒绝，不是默认放行** |

**必须支持的匹配形式（对应 `modules/M6` §3.3 的七类绕过防御）：**

| 输入形式 | 归一化要求 |
|---|---|
| 十进制 IP `3232235777` | 转为点分十进制后匹配 |
| 八进制 `0177.0.0.1` | 同上 |
| 十六进制 `0x7f.0.0.1` | 同上 |
| IPv6 映射 IPv4 `::ffff:10.40.23.1` | 展开后匹配 |
| 带 userinfo 的 URL `http://allowed@evil.com` | **取 host 而非 userinfo** |
| 短域名 / 通配符 DNS | 解析后按 post_dns 层复核 |
| 超长域名 / 尾点 `evil.com.` | 长度上限 + 规范化 |

## 4. ROE（交战规则）字段

```yaml
actions:
  allow:
    - recon            # 信息收集
    - scan             # 漏洞扫描
    - fuzz             # 参数/路径模糊测试
    - exploit          # 漏洞利用（获得访问权限）
    - post_exploit     # 后渗透（横向、提权、凭据收集）
    - enumerate        # 枚举
  deny:
    - dos              # 拒绝服务（默认禁止）
    - destructive      # 破坏性操作（删库、格式化）
    - ransomware_sim   # 勒索软件模拟
    - social_engineering
    - physical
    - supply_chain
    - data_exfiltration  # 数据外带（读取即记录，不外传）

  limits:
    max_requests_per_second: 10        # 单目标速率上限
    max_concurrent_tasks: 3
    max_depth_hops: 3                  # 内网横向最大跳数
    forbidden_payloads:                # 载荷黑名单（内容级）
      - destructive
      - persistent_backdoor            # 持久化后门需显式授权才允许
    allowed_hours: "09:00-18:00 Asia/Shanghai"
    allowed_days:  [MO, TU, WE, TH, FR]
```

**设计要点：**

| # | 要点 |
|---|---|
| **1** | `allow` 是**白名单** —— 未列出的动作默认禁止 |
| **2** | `deny` 是**显式声明** —— 用于记录"明确不允许"，增强审计可读性 |
| **3** | **`dos` / `destructive` 默认永远在 deny 中**，即使 allow 里没写也不可执行（硬编码保护） |
| **4** | 时间窗是**执行时校验**，不是启动时校验一次 |
| **5** | `persistent_backdoor`（持久化）默认禁止 —— 需在 allow 中显式加入才可执行 |

## 5. 越界判定与熔断

### 5.1 三重校验（与 `modules/M6` §3.1 一致）

```
出站请求
   ├─ L1 network:      目标 IP/CIDR 是否在 include 且不在 exclude
   ├─ L2 tool_param:   工具参数中的 target 字段是否通过校验
   └─ L3 post_dns:     DNS 解析后的真实 IP 再复核
```

### 5.2 判定结果

```protobuf
message ScopeCheckResult {
  bool allowed = 1;              // 无中间态
  ScopeLayer failed_layer = 2;   // NETWORK / TOOL_PARAM / POST_DNS
  string decision_id = 3;        // 裁决记录 ID（写入审计）
  string reason = 4;             // 具体原因（如 "excluded by cidr 10.40.23.128/25"）
}
```

### 5.3 熔断语义（不可协商）

| 情形 | 动作 |
|---|---|
| `include` 未命中 | **DENY** |
| `exclude` 命中 | **DENY** |
| 动作不在 `allow` 中 | **DENY** |
| 时间窗之外 | **DENY** |
| 速率超限 | **拒绝该请求**（可重试，不熔断整场） |
| **任何 DENY** | **立即熔断整场会话** + 退出码 4 + 审计事件 |

**"立即熔断整场会话"的理由：** 一次越界尝试意味着**要么配置有误、要么 agent 已被诱导（T1）**。两种情况下继续运行都是不安全的。跳过该请求继续执行会掩盖问题。

### 5.4 Scope 变更

```
运行期需要修改 scope
   │
   ├─ WebUI 是否提供"修改 scope"功能？──▶ 否（不提供）
   │
   └─ 唯一路径：
        1. 停止当前会话
        2. 修改 roe.yaml
        3. 通过 CLI 重新提交（aleth run --authorization roe.yaml）
        4. 新会话启动，凭证哈希写入审计日志

明确不提供的能力：
  ❌ "临时批准这次越界"按钮（会变成绕过 Authorization Anchor 的后门，见 07 §T5.5）
  ❌ 运行期热改 scope
  ❌ 通过 MCP 修改 scope
```

## 6. 审计要求

### 6.1 必须记录的事件

| 事件 | 记录内容 |
|---|---|
| 进程启动 | 凭证哈希、scope 哈希、时间、版本 |
| 每次 Scope 裁决 | decision_id、目标、结果、失败层、原因 |
| 每次工具执行 | exec_id、工具、argv（脱敏后）、时间 |
| 每次熔断 | 触发条件、上下文快照 |
| 凭证变更 | 旧哈希 → 新哈希、操作者 |
| 会话结束 | 统计摘要、退出码 |

### 6.2 日志保护

| 要求 | 实现 |
|---|---|
| 防篡改 | append-only + 哈希链（断链即告警） |
| 不含敏感值 | 日志中只有 Privacy Gateway 的 token，无真实 IP/凭据 |
| 可导出 | 支持导出审计包（供客户/监管查阅） |
| 保留期 | 默认 90 天（可配置，见 `data_handling.retention_days`） |

### 6.3 数据处理要求

```yaml
data_handling:
  pii_handling: "mask"                # mask | allow（默认 mask）
  retention_days: 90
  no_external_transmission: true       # 不外传给模型供应商（Privacy Gateway 强制）
  evidence_export_allowed: ["client"]  # 证据导出范围
```

## 7. 合规声明模板

**每次评估结束后，报告必须包含以下声明（自动生成，不可省略）：**

```
═══════════════════════════════════════════════════════════
授权与合规声明
═══════════════════════════════════════════════════════════
授权方        : <granted_by>
被授权方      : <granted_to>
授权凭证      : <ticket_id> / <document_hash 前 12 位>
有效期        : <valid_from> ~ <valid_until>
评估时间      : <session_start> ~ <session_end>

范围（included）:
  - 10.40.23.0/24
  - app.example.com (80, 443, 8080)

范围（excluded）:
  - 10.40.23.128/25
  - pay.example.com

允许动作      : recon, scan, fuzz, exploit, post_exploit
速率限制      : 10 req/s per target, 3 concurrent

越界拦截记录  : 0 次
预算消耗      : <consumed> / <total>
数据外传      : 无（Privacy Gateway 全程启用）
凭证哈希      : sha256:<...>
审计日志哈希链: 完整（末条 self_hash: <...>）

声明：本次评估严格在上述授权范围内执行。所有对外数字
      由 benchmarks/ 脚本产生，可被第三方复现。评估过程
      中所有真实敏感值均经 Privacy Gateway 脱敏，未传输
      至任何外部服务。
═══════════════════════════════════════════════════════════
```

**硬约束：** 若 `越界拦截记录 > 0`，声明中必须**显式标注**并说明处置过程。**不允许隐藏拦截记录** —— 拦截本身是安全机制生效的证明，不是失败。

## 8. 法律依据

### 8.1 中国法律（主要适用）

| 法律 | 相关要求 |
|---|---|
| **《中华人民共和国网络安全法》** | 未经授权扫描/渗透第三方系统违法；新修订版本新增 AI 安全条款 |
| **《中华人民共和国数据安全法》** | 数据分类分级；跨境数据传输管理 |
| **《中华人民共和国个人信息保护法》** | 评估中接触到的个人信息需最小化、脱敏、限定用途 |
| **《网络数据安全管理条例》** | 年度合规审计；数据跨境管理 |

### 8.2 项目立场

**三条不可妥协的立场：**

1. **仅限授权测试。** 无授权凭证不启动（技术强制，非口头约定）。
2. **未授权扫描/渗透第三方系统是违法行为。** 本项目不为此提供任何便利。
3. **项目方不承担使用者滥用行为的法律责任**，但**有责任设置最低技术门槛**（Authorization Anchor + 速率限制 + 审计留痕）。

### 8.3 欧盟

| 法规 | 要求 | 对本项目的约束 |
|---|---|---|
| **GDPR** | 数据最小化；处理个人数据需合法性基础；跨境传输需适当保障 | 评估中接触到的个人信息必须经 Privacy Gateway 脱敏；`pii_handling` 必须为 `mask` |
| **EU AI Act** | 对"高风险 AI 系统"要求风险评估、技术文档、人类监督、事件报告 | 自主渗透系统应归类为需人类监督的范畴 → **人机协同决策队列不是可选功能**（`06` §7.1） |
| **NIS2** | 关键基础设施运营者的网络安全与事件报告义务 | 若客户属于 NIS2 范围，事件通知时限按 NIS2 执行（通常 24 小时早期预警） |

**额外要求（欧盟）：**

| # | 要求 |
|---|---|
| 1 | 需准备**技术文档**（本项目的 `docs/` 可直接作为基础） |
| 2 | 需有**人类监督机制**的说明（本项目的人机协同决策队列） |
| 3 | 事件发生后需在 24 小时内向监管早期预警（若涉及 NIS2 主体） |
| 4 | 涉及跨境传输时，需 SCC（标准合同条款）或其他适当保障 |

**声明模板增量字段：**

```
适用法规        : GDPR / EU AI Act / NIS2（如适用）
个人数据处理    : 全程经 Privacy Gateway 脱敏，无原始个人信息出域
人类监督        : 已启用（人机协同决策队列，触发条件见 06 §7.1）
跨境传输        : 无 / 有（保障措施：SCC 编号 XXX）
数据主体权利    : 评估结束后 X 日内可申请查阅/删除评估数据
```

### 8.4 美国

| 要点 | 说明 |
|---|---|
| **CFAA（18 U.S.C. § 1030）** | "exceeding authorized access" 是刑事风险 —— **因此授权范围必须字面明确**。本项目要求 `targets.include` 显式列举，不接受"整个 /16 段"这类宽泛授权 |
| **州法差异** | 加州 CCPA/CPRA、纽约 SHIELD Act 等对个人信息处理有额外要求 |
| **关键基础设施** | 若目标涉及 CI，需额外授权层级（通常需资产所有方书面同意 + 可能需向 CISA 报备） |
| **DMCA § 1201** | 若评估涉及绕过技术保护措施，需单独授权（本工具不涉及，但需在使用说明中声明） |

**声明模板增量字段：**

```
适用法规        : CFAA / 州法（列举，如 CCPA）
授权范围明确性  : 已显式列举（不依赖宽泛授权）
关键基础设施    : 否 / 是（额外授权文件：XXX）
```

### 8.5 跨境评估

**判定：只要评估涉及的任一环节跨越司法辖区，即为跨境评估。**

| 环节 | 跨境风险点 |
|---|---|
| 目标位置 | 目标服务器在境外 |
| 操作者位置 | 执行评估的人员在境外 |
| 数据处理位置 | 数据存储或处理在境外 |
| **模型调用位置** | **模型 API 在境外（最常见、最容易被忽略）** |

**跨境评估的强制要求：**

| # | 要求 | 理由 |
|---|---|---|
| 1 | `no_external_transmission` 必须为 `true` | 禁止目标数据出境 |
| 2 | **必须使用本地模型**（Ollama / vLLM），不得调用境外模型 API | Privacy Gateway 只脱敏敏感值，**不脱敏"目标存在什么"这类元信息**；元信息出境本身可能构成风险 |
| 3 | 需在声明中标注跨境情况与保障措施 | 合规可追溯 |
| 4 | 若使用境外模型，需 SCC 或其他适当保障并留档 | GDPR / 数据安全法要求 |

**注意第 2 条的必要性：** 即使 Privacy Gateway 把 `10.40.23.191` 替换为 `IP_PRIVATE_001`，模型仍会看到"某私有网段有 40 台主机、运行 nginx 1.24.0、存在 3 个可利用缺陷"这类**结构性元信息**。对某些客户，这本身就是敏感信息。**因此跨境场景下唯一安全的做法是本地模型。**

### 8.6 辖区快速对照

| 维度 | 中国 | 欧盟 | 美国 |
|---|---|---|---|
| 主要法律 | 网络安全法 / 数据安全法 / 个人信息保护法 | GDPR / EU AI Act / NIS2 | CFAA + 州法 |
| 授权要求 | 书面授权 | 书面授权 + 合法性基础 | **范围必须字面明确**（CFAA 风险） |
| 个人信息 | 最小必要 + 告知同意 | 最小化 + 合法性基础 + 数据主体权利 | 州法差异大 |
| 事件通知 | 法规规定时限 | 24h 早期预警（NIS2） | 州法差异（通常 72h） |
| AI 专项 | 新修订网安法含 AI 条款；生成内容标识办法 | **EU AI Act（最严格）** | 以行业指引为主 |
| 跨境传输 | 需安全评估/标准合同/认证 | 需 SCC 等保障 | 州法差异 |
| **本项目强制项** | Authorization Anchor + 脱敏 | 人类监督（HITC 队列）+ 技术文档 | 范围字面列举 |
