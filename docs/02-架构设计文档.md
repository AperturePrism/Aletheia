## 1. 项目定位

### 1.1 团队与项目

| | 名称 | 含义 |
|---|---|---|
| **团队** | AperturePrism | 光圈 + 棱镜。光学观测系统的两个核心元件：**光圈决定"看多少"**，**棱镜决定"看到哪些维度"** |
| **项目** | Aletheia | 古希腊语 ἀλήθεια（a- 表否定 + lēthē 表遮蔽），意为"**去蔽**"。海德格尔用它指"让被遮蔽之物自行显现"。这正是本项目的第一原则 —— **不是生成结论，而是让证据显现** |

命名与架构同源：**团队名描述观测手段（怎么看清），项目名描述观测目的（让什么显现）**。

### 1.2 一句话定义

**Aletheia 是 AperturePrism 团队研发的、以"可证明性"为第一原则的自主渗透测试系统：把混沌的工具输出通过棱镜分解为结构化证据光谱，用可调光圈按需投喂 LLM 上下文，并只允许落在焦平面上的、有可复现证据的结论成为正式发现。**

### 1.3 交付形态（摘要）

**Aletheia 是一个自托管的本地服务（daemon），以 WebUI 为主界面，CLI 为控制平面，MCP 为集成接口。**

| 载体 | 定位 |
|---|---|
| `alethd` 守护进程 | 核心服务，承载全部业务逻辑与 API |
| **WebUI** | **主界面** —— 任务编排、实时观测、证据浏览、人机协同决策 |
| `aleth` CLI | 控制平面 —— 启动/停止、脚本化、CI 集成、状态查询 |
| MCP 接口 | 集成 —— 双向（消费外部工具 / 被外部 agent 调用） |

**明确不做：** 桌面 GUI（Electron/Tauri）、移动 App、浏览器扩展。

选择 WebUI 为主界面的核心原因：本项目的三个差异化能力（**证据链浏览、光圈上下文投影可视化、冲突矩阵**）在结构上无法用命令行有效表达。**如果只有 CLI，这些能力用户感知不到，项目会退化成一个普通的 CLI 渗透 agent。**

> 完整论证、竞品形态对照、部署模式（单机/团队）、WebUI 信息架构与交互设计见 **`06-交付形态与交互载体.md`**。

### 1.4 命名与架构的映射（不是装饰，是设计约束）

| 概念 | 来源 | 隐喻 | 架构映射 |
|---|---|---|---|
| **Aletheia（去蔽）** | 项目名 | 让被遮蔽之物自行显现 | **反幻觉第一原则**：结论必须由证据显现而来，不可由模型声称而生 |
| **Prism（棱镜）** | 团队名 | 白光分解为按波长排列的光谱 | 把混合了资产/服务/凭据/缺陷的原始输出，分解为正交维度的**结构化证据光谱** |
| **Aperture（光圈）** | 团队名 | 孔径决定进光量与景深 | **动态控制进给 LLM 的信息孔径**；进光量与景深互相约束（不能既大又深） |
| **Focal Plane（焦平面）** | 架构概念 | 只有准确落在焦平面上的光才形成清晰像 | **只有挂载了可复现证据的结论才能"成像"**；未成像的只是散焦的假设 |
| **Chromatic Correction（色差校正）** | 架构概念 | 不同波长折射率不同导致成像模糊 | **黑盒 / 白盒 / 二进制三路交叉验证**，校正单一视角的畸变 |
| **Autofocus（自动对焦）** | 架构概念 | 自动寻找最清晰的焦点 | 依据当前假设自动选择观测孔径与关注维度 |

### 1.5 目标与非目标

**目标（v1.0）：**
- 在公开基准上给出**可复现、可对比**的分数（不接受"我们很强"式的自述）
- 所有进入报告的发现，**100% 附可复现 PoV 与执行证据**
- 支持**完全离线**运行（本地模型 + 无外联）
- 攻击路径**可回溯、可分支、可回放**
- 单次评估成本**可控且有硬上限**

**明确非目标（v1.0 不做）：**
- 不做通用 Agent 框架（不做 LangChain 替代品）
- 不做 0day 挖掘（那是 T4/T5 类工具的领域，Aletheia 消费而非重建）
- 不追求"全自主无人值守"作为卖点（**调研结论明确：全自主 = 21%，有人类提示 = 64%。把人类放在高价值决策点上不是缺陷，是设计**）
- 不承诺替代人类渗透测试员
- 不做桌面 GUI、移动 App、浏览器扩展（见 §1.3）

## 2. 设计原则

### 2.1 去其糟粕 —— 已识别缺陷的对策映射

调研归纳出 20 项缺陷（D1–D20），下表给出逐条对策。**没有对策的缺陷不会进入本项目。**

| 缺陷 | 业界现状 | Aletheia 对策 | 落在哪个模块 |
|---|---|---|---|
| **D1 幻觉式成功** | 字符串匹配判成功 → "23/23 攻破"实际 0 个 shell | **证据正则 + 执行痕迹双要素校验**。`breach_confirmed()` 必须同时满足：① 目标侧副作用可观测（`uid=0` / 新增账号 / 文件落地）② 工具侧执行日志可追溯。任一缺失即降级为 Hypothesis | M4 Focal Plane |
| **D2 自言自语** | agent 幻想命令输出并在其上继续推理 | **执行-观察强绑定**：任何 Observation 必须携带 `exec_id`（沙箱真实执行记录哈希）。无 exec_id 的输出视为虚构，直接丢弃并触发熔断计数 | M4 + M6 Sandbox |
| **D3 Flag 幻觉** | 找到任意 Base64/哈希即宣告胜利并终止 | **终止需授权**：agent 无权自行终止会话。终止请求必须提交"目标达成证据包"，由独立 **Termination Arbiter** 校验（目标归属 + 证据充分性）。校验失败则打回并继续 | M4 Arbiter |
| **D4 上下文失忆** | 早期线索被挤出上下文，20 步后遗忘 | **Aperture Control**：上下文不承载记忆，记忆在图结构心智地图中。上下文只是当前焦点的**投影**，可随时按需重新投影。**信息不因离开上下文而丢失** | M3 + M2 |
| **D5 业务逻辑盲区** | 70% 关键漏洞，全行业失明 | **Intent Modeling**：从 OpenAPI/流量/源码/文档抽取应用的"预期行为契约"，做**契约违背检测**而非模式匹配。业务逻辑漏洞必须靠"应该做什么"与"实际做了什么"的差异来发现 | M8 Intent Modeler |
| **D6 多步链式弱** | 链式任务成功率 ~16%，发现无法传递到利用阶段 | **心智地图为唯一真源**：侦察阶段发现的凭据/版本/cookie 以类型化实体写入地图，利用 agent 从地图查询而非从上下文回忆。**跨阶段传递不依赖 LLM 记忆** | M2 Mental Map |
| **D7 多会话状态混淆** | IDOR 场景混淆 A/B 账号 cookie，产生假阴性 | **会话为一等对象**：Session 是独立实体（含 cookie/token/权限集），请求必须显式绑定 `session_id`。跨会话操作需显式声明，由编排器校验 | M8 + M2 |
| **D8 RAG 负收益** | 外部知识库常产生负回报，低精度检索引入幻觉 | **RAG 降级为可选且带准入**：检索结果必须通过相关性阈值（且**宁缺勿滥**），未过阈值则不注入。默认关闭，按需开启并记录每次注入的命中率用于事后评估 | M2（向量检索部分） |
| **D9 工具契约脆弱** | 参数名不匹配静默拒绝、ANSI 污染、版本串混淆 | **三层防御**：① **禁止 LLM 直接拼命令行** —— 工具调用走参数化 Schema，由确定性适配器渲染为 argv ② 输出强制 `strip_ansi()` 后再解析 ③ 解析器用**类型化断言 + 单元测试**覆盖边界（如 nmap 版本串 "2 (RPC #100000)" 的前导数字守卫） | M1 Tool Adapter |
| **D10 工程可靠性** | AIxCC：多数队伍因崩溃/配置错误丢分；稳定性 > 技术先进性 | **可靠性优先于能力**：核心验收标准包含"连续 143 小时无崩溃"的稳定性测试（对齐 AIxCC 赛制）。所有外部调用有超时/重试/降级，所有状态可恢复 | 全局（M5 + M6 Checkpoint） |
| **D11 范围控制弱** | agent 触碰未授权系统 | **Scope Kernel**：范围是内核级约束，非提示词约定。三重执行：① 网络层出站白名单（CIDR/域名）② 工具层目标参数校验 ③ 请求层 DNS 解析后 IP 复核。**越界即 fail-closed 熔断**，不降级 | M6 Scope Kernel |
| **D12 编排脆弱·级联失败** | 侦察漏一个服务，下游永不测试 | **不依赖单一侦察结果**：心智地图的资产维度允许多源写入（主动扫描 / 被动流量 / 白盒源码 / 历史数据），任一来源发现即入图。**级联失败被"多源冗余"消解** | M2 Prism Decomposition |
| **D13 过度自信·信号噪声混淆** | 把产出量当价值 | **报告分层**：Confirmed（有 PoC，进主报告）/ Candidate（强证据待验证，进附录）/ Hypothesis（推测，仅调试可见）。**主报告只放 Confirmed** | M4 Focal Plane |
| **D14 可观测性缺失** | 无法回答"为什么这么做""证据是什么" | **全链路 OTel + 决策溯源**：每个 agent 决策记录其依据的地图实体 ID；每个 finding 可回溯到具体 exec_id 与原始工具输出行号 | M6 Observability |
| **D15 数据主权外泄** | 真实 IP/凭据送云端模型 | **Privacy Gateway 默认开启**（非可选）：确定性脱敏 token（`IP_PRIVATE_001` / `HOST_INTERNAL_001` / `CRED_001`）双向映射，映射表仅存本地且不落日志。**出站流量二次扫描**，检出未脱敏敏感值即阻断 | M6 Privacy Gateway |
| **D16 武器化滥用** | HexStrike 被用于自动化攻击真实 Citrix 漏洞 | **授权锚定**：启动必须提供授权凭证（授权书哈希 / 工单号 / ROE 文件），凭证与 scope 绑定并写入审计日志。**无授权凭证不启动**（不是警告，是拒绝）。另提供**速率上限**防止被当作规模化攻击工具 | M6 Authorization Anchor |
| **D17 生态锁定** | Claude Code 原生范式锁定单一供应商 | **模型中立 + Harness 可换**：抽象 Model Provider 接口，任何单一模型不得成为架构假设。Harness 层可选（外部 CLI agent 优先，但可降级为内置循环） | M5 + providers |
| **D18 遥测默认开启** | 默认向第三方发遥测 | **零遥测默认**：默认不发送任何遥测。如需开启必须显式 opt-in，且发出内容经过 Privacy Gateway 脱敏 | M6 Telemetry Policy |
| **D19 默认配置不安全** | 默认口令 + 自签证书 | **安全默认**：首次启动强制生成随机口令并强制修改；默认仅监听 127.0.0.1；无 TLS 证书时拒绝对外暴露而非自签降级 | M6 Bootstrap |
| **D20 Bus factor 高** | 核心提交集中于单人 | **可替换性设计**：模块边界清晰、接口稳定、关键路径有测试覆盖与文档。目标：任一模块可被第三方独立重写 | 架构原则 |

### 2.2 取其精华 —— 应当吸收的优秀设计

| 来源 | 精华设计 | 采纳方式 |
|---|---|---|
| **CHECKMATE** | LLM 不擅长长程规划 → 让 LLM 生成 PDDL，经典规划器求解；成功率 +20%、快 50%、省 50% | **采纳为核心**：编排层用"LLM 生成任务图 + 确定性规划器求解"，而非纯 LLM 逐步决策 |
| **VulnBot** | 渗透任务图（PTG）：节点=任务，边=依赖，跨会话持久 | **采纳并扩展**：升级为心智地图（不只是任务依赖，而是全实体关系图） |
| **PentAGI** | 四层记忆（长期/工作/情景/知识图谱）+ chain summarization；平台化（API/可观测/沙箱） | **采纳记忆分层思想**，但改为**单一大图 + 多视图**（见 modules/M2），避免四套存储的同步开销 |
| **D-CIPHER** | **Auto-prompter**：第三个 agent 观察失败模式并重写其他 agent 的指令 | **采纳**：新增 Refiner 角色，基于失败模式库动态修正 agent 指令，而非简单重试 |
| **D-CIPHER / HPTSA** | 多 agent 层级分工显著优于单 agent（4.3×） | **采纳层级结构**，但**只在高价值环节启用多 agent**（对齐 PentestEval 结论：ReAct 常已足够，多 agent 不是免费午餐） |
| **Strix / Shannon** | 只把有可复现 PoC 的漏洞纳入报告；Shannon 白盒 96.15% | **采纳为第一原则**（本项目核心差异化，见 modules/M4） |
| **Darkmoon** | Privacy Gateway：确定性脱敏 token，模型永不见真实值；真值在工具执行前本地回注 | **采纳并设为默认**（Darkmoon 是少数正确解法，但它是可选设计；本项目设为强制路径） |
| **pentestagent (GH05TCREW)** | 对话 rewind/fork 分支；MCP 工具数 >128 时切 embedding 检索层；`spawn_mcp_agent` 隔离子 agent | **全部采纳**：分支管理、工具检索层、子 agent 隔离 |
| **AIxCC Buttercup** | 拒绝高端推理模型，主打中端模型 + 工程化；置信度 <98% 需人工复核；150ms 复核窗口 | **采纳**：模型分级路由 + 置信度阈值触发**人机协同决策**（由 WebUI 承载，见 `06`） |
| **AIxCC Atlantis** | **把系统鲁棒性作为首要任务**；融合优先（ensemble 而非单一路线） | **采纳为首要工程目标** |
| **AIxCC 评分机制** | Bundle 关联机制：**错误关联重罚**（-7 分） | **采纳**：证据账本中，错误归因触发严重告警并回滚 |
| **xOffense / CIPHER** | 领域微调的中等模型 > 通用大模型（Qwen3-32B 微调达 79.17%） | **采纳为 P3 路线**：收集运行轨迹，微调专用小模型用于高频子任务 |
| **CSI Blackboard** | 多 scaffold 共享黑板交换类型化发现 → 57.6% > 单一最佳 45.5% | **采纳思想**：心智地图即 Blackboard，但用**类型化实体 + 事务**替代纯文本笔记 |
| **GCAI** | 1,344 行 TS 实现单次利用成本 $0.56（比 Claude 低 3.5×） | **采纳"极简优于堆砌"的取向**：能用确定性代码解决的绝不用 LLM |
| **Capybara / Superagent** | 公开 CTF 基准从 89.4% 提升到 100%（104/104） | 作为 harness 能力上限的参照系 |

### 2.3 查漏补缺 —— 六个行业空白的设计承接

| 空白 | 行业现状 | Aletheia 设计 |
|---|---|---|
| **G1 可证明性** | 仅少数项目要 PoC，无人把证据作为一等数据结构 | **Evidence Ledger（证据账本）**：与心智地图平行的独立存储，每条记录含 exec_id、原始输出指纹、复现脚本、副作用观测。**焦平面只承认账本中有据的结论**（modules/M4） |
| **G2 业务逻辑** | 70% 关键漏洞失明 | **Intent Modeler**：构建"预期行为契约"，做契约违背检测（modules/M8） |
| **G3 结构化持久记忆** | PentAGI 最好但仍偏"检索式" | **Mental Map**：单一属性图承载 7 类实体 + 关系，支持时间版本与假设分支；**主动推送**而非被动检索（modules/M2） |
| **G4 跨范式融合** | 黑盒/白盒/二进制完全割裂 | **三路观测融合**：三路观测器向同一地图写入，**冲突即高价值信号**（modules/M7） |
| **G5 成本硬治理** | 无硬约束，"死循环烧 token" | **Cost Governor**：预算是一等约束，超限即熔断（非告警）。剩余额度决定光圈开度（modules/M6） |
| **G6 数据主权** | 仅 Darkmoon，且为可选 | **Privacy Gateway 默认开启**（modules/M6） |

## 3. 总体架构

### 3.1 分层视图

```
┌──────────────────────────────────────────────────────────────────────┐
│  L4  Orchestration Layer（编排层）                                    │
│  ┌────────────┬────────────┬────────────┬────────────┐              │
```

## 5. 跨范式融合（摘要）

> **完整设计见 `modules/M7-三路融合.md`。** 本节仅保留对架构有约束力的核心结论。

**三路观测**（黑盒运行时 / 白盒源码 / 二进制）向**同一心智地图**写入，各自带 `SourceKind` 标记，冲突以 `CONTRADICTS` 关系落图，**不合并**。

**冲突矩阵（最高价值象限）：**

| 黑盒 | 白盒 | 解读 | 优先级 |
|---|---|---|---|
| 可利用 | 有缺陷 | 双源确认 | 高 |
| **打不通** | **有缺陷** | **利用条件未满足 / 需前置认证** | **最高 —— 可能是链式漏洞第一环** |
| 可利用 | 无缺陷 | 配置类问题或白盒漏检 | 中 |
| 打不通 | 无缺陷 | 可能确实安全 | 低 |

**对架构的约束：**
- M3 光圈投影给 `CONTRADICTS` 关系高权重（0.85），冲突实体优先呈现
- M5 据此派生深挖任务
- 报告必须声明**观测覆盖度**（三路不是总能齐全，默认假设会产生过度自信）

**行业空白：** 调研的 39+ 个项目中，**没有任何一个统一了三路观测** —— 黑盒 agent 不做代码分析，白盒工具（VulnHuntr）仅 Python 且有 CLI 无编排，二进制工具（VulHunt）完全独立。

## 6. 业务逻辑检测（摘要）

> **完整设计见 `modules/M8-业务逻辑意图建模.md`。** 本节仅保留对架构有约束力的核心结论。

**要解决的是全行业唯一被点名的 0% 区域。** ARTEMIS 研究（8,000 台主机实网，AI 排名第 2，击败 10 名人类中的 9 名）明确指出：**关键 Web 漏洞中约 70% 属于业务逻辑缺陷，当前没有任何自主 agent 能可靠检测。**

**方法：契约违背检测，而非模式匹配。**

`POST /transfer {from: A, to: B, amount: 100}` 本身完全合法 —— 问题在于 A 是否有权从别人账户转账。这需要理解**授权语义**。

**六类契约违背：** 越权访问（BL1）/ 价格数量篡改（BL2）/ 流程绕过（BL3）/ 配额绕过（BL4）/ 权限提升链（BL5）/ 竞态（BL6）。

**对架构的约束：**
- **Session 必须是一等实体**（BL1 依赖它，同时解决 D7 多会话状态混淆）
- 越权判定必须基于 `DATA_RETURNED` 副作用观测，**禁止仅凭状态码**
- 报告必须**分场景统计**（有契约 / 无契约）—— 只报有契约的数字会高估能力

**诚实边界：** 契约抽取依赖可获取的输入（OpenAPI / 源码 / 流量）。对完全黑盒且无文档的目标只能做流量启发式推断，覆盖率显著下降。**此限制写入文档与报告，不做过度承诺。**

## 7. 技术选型

### 7.1 语言与运行时

**核心矛盾：** Python 拥有压倒性的安全工具生态（pwntools / impacket / angr / scapy / 各类 POC）；Go/Rust 在并发、单二进制分发、沙箱控制上更优（PentAGI 用 Go 就是例证）。

**推荐方案：双语言分层**

| 层 | 语言 | 理由 |
|---|---|---|
| L0 工具适配 / 解析器 / Scope Kernel / Sandbox / Gateway / Governor | **Go** | 高并发、单二进制、出站代理与网络控制成熟、无解释器依赖、crash 面小（对齐 AIxCC"稳定性优先"） |
| L1–L3 心智地图 / 光圈 / 焦平面 | **Python**（核心逻辑）+ **Rust**（图算法热点扩展） | 快速迭代；图遍历热点用 PyO3 扩展 |
| L2 上层 Agent / 编排 | **Python** | LLM SDK 生态、快速实验 |
| **CLI（`aleth`）** | **Go** | 单二进制分发，无需运行时依赖 |
| **WebUI** | **React + TypeScript**（Vite 构建，**不做 SSR**） | 本地工具无 SEO 需求；与 daemon 的 API 直连 |

**保守替代方案（单语言）：** 全部用 Python（`uv` 管理依赖）。优势是开发速度最快、贡献门槛最低；劣势是长期运行稳定性与分发体验差于 Go。**若项目以"学术验证 / 快速迭代"为首要目标，选此方案。**

**决策：** 本项目把 Reliability 列为第一工程目标，**推荐双语言分层**，但允许 v0.1 原型阶段全 Python 起步，在 L0 稳定后迁移至 Go（契约先定死，迁移只换实现）。

### 7.2 存储

| 用途 | 单机模式 | 团队模式 | 理由 |
|---|---|---|---|
| 心智地图（属性图） | SQLite + 图扩展 | PostgreSQL + Apache AGE | 避免 Neo4j 的额外运维负担。**不采纳"四套存储"路线** |
| 向量检索（辅助） | sqlite-vec | pgvector | 与主库同源，避免同步问题 |
| 证据账本 | SQLite（WAL） | PostgreSQL | 强一致 + 可审计；append-only 语义 |
| 原始工具输出 | 文件系统（内容寻址） | 对象存储 / 共享卷 | 大文件不入库；账本只存引用与指纹 |
| 检查点 / 分支快照 | 内容寻址 + 图版本号 | 同左 | 支持 rewind/fork 与回放 |
| 审计日志 | append-only + 哈希链 | 同左 | 防篡改 |

**单机与团队模式共用同一套 schema 与代码**，通过配置切换驱动（见 `06` §5）。

### 7.3 模型层

| 需求 | 方案 |
|---|---|
| 抽象接口 | 自研薄适配层（对齐 LiteLLM 能力但去掉其重依赖）；支持 OpenAI 兼容 / Anthropic / Gemini / Ollama / vLLM |
| 分级路由 | 高确定性任务（解析辅助、报告整理）→ 小模型/本地；高不确定性（利用链推理）→ 前沿模型 |
| 本地优先 | 完整离线能力（对齐 CAI 的 300+ 后端与空气隔离场景） |
| 微调路线 | P3 阶段：收集运行轨迹，微调 Qwen 系中等模型用于高频子任务（依据 xOffense/CIPHER 结论：领域适配 > 规模） |
| Harness 可选 | 支持外部 CLI agent（Claude Code / Codex）作为可替换执行器，但**不作为架构假设**（反 D17） |

### 7.4 沙箱与隔离

| 需求 | 选型 |
|---|---|
| 容器隔离 | Docker（默认）/ Kata Containers（高安全场景） |
| 网络控制 | 出站代理 + Scope Kernel 校验 + DNS 复核 |
| 文件系统 | 容器内只读基础镜像 + 临时工作卷 |
| 凭据隔离 | 宿主凭据不入容器；容器内凭据由 Sandbox 临时注入 |
| exec_id 签发 | Sandbox 侧签名，agent 无法伪造 |

### 7.5 可观测性

OpenTelemetry（trace/metrics/log）+ Grafana/Loki（自托管，团队模式）+ **WebUI 内置轻量查看器（单机默认）**。

**零遥测：** 不用必须云端的 SaaS 方案。本地查看器由 WebUI 承载 —— 这也是 WebUI 成为必需品而非可选项的技术原因之一。

| 中国法律 | 遵守《网络安全法》《数据安全法》《个人信息保护法》；**未授权扫描/渗透第三方系统违法** |
| 欧盟 | 若涉及欧盟主体，注意 EU AI Act 对自主系统的评估与事件报告要求 |
| 速率限制 | 内置上限，防止被用于规模化攻击 |

### 11.2 技术风险

> **完整风险登记册（含概率、影响、缓解、触发条件）见 `04-开发总纲` §9。**

最高优先级的三项：光圈召回率不达标（影响高）、Intent Modeler 黑盒覆盖率低（概率高）、关键路径人力不足（影响高）。

### 11.3 自身安全（本项目自己也是一个 AI 系统）

必须纳入威胁模型（详见 `docs/07-threat-model.md`）：

- **Agent 被目标诱导**：目标页面注入提示词，诱导 agent 越界 → Privacy Gateway 出站扫描 + Scope Kernel 网络层兜底 + 提示注入检测
- **工具投毒**：恶意 MCP server / 被篡改的工具 → 工具白名单 + 适配器签名校验
- **Agent 逃逸**：容器逃逸获取宿主凭据 → 无宿主凭据入容器 + 只读基础镜像 + 最小权限
- **证据伪造**：agent 伪造 exec_id → exec_id 由 Sandbox 签发并签名
- **界面侧风险**（WebUI 引入）：本地服务被其他进程访问 → 默认仅监听 127.0.0.1 + 启动时生成一次性令牌；浏览器端 XSS 导致凭据泄漏 → 凭据不入前端，全部经 Privacy Gateway 脱敏

## 12. 差异化总结

| 维度 | 行业现状 | Aletheia |
|---|---|---|
| **证据处理** | 少数要 PoC，多数靠字符串匹配 | 证据账本为一等结构，四道闸门，主报告仅含可复现确认项 |
| **上下文管理** | 上下文当记忆用，失忆是常态 | 记忆在图里，上下文是焦点的投影；光圈预算硬约束 |
| **持久记忆** | 检索式（pgvector）或纯上下文 | 单一属性图 + 7 视图 + 时间版本 + 假设分支；主动推送 |
| **规划** | 多数让 LLM 逐步决策 | LLM 生成任务图 + 确定性规划器求解 |
| **范式覆盖** | 黑盒/白盒/二进制三线割裂 | 三路观测融合 + 冲突矩阵 |
| **业务逻辑** | 全行业 ≈0% | Intent Modeling 契约违背检测 |
| **终止控制** | agent 可自行宣告成功并终止 | 无权终止，须经独立 Arbiter 校验 |
| **成本** | 无硬约束 | 预算一等公民，超限硬熔断 |
| **数据主权** | 多数默认送云端 | Privacy Gateway 默认强制 |
| **范围控制** | 提示词约定 | 内核级三重校验 + fail-closed |
| **可靠性** | 工程问题拖累能力 | 列为第一工程目标，143h 稳定性验收 |
| **可复现性** | 大量自述数据 | 公开 harness，所有数字可第三方重跑 |
| **生态中立** | 常锁定单一供应商 | 模型中立 + Harness 可换 |
| **交付形态** | HexStrike 把 UI 外包给第三方客户端（实测体验不可控） | **自托管服务 + 自研主界面**，三个差异化能力有专门视图 |

### 立得住的三个"第一"

1. **第一个把"证据"作为一等数据结构**（而非事后补 PoC）的 AI 渗透系统
2. **第一个统一黑盒/白盒/二进制三路观测**并输出冲突矩阵的系统
3. **第一个给出可复现的业务逻辑漏洞检出数字**的系统（若 P2 达成）

**同时坦诚承认的边界：** 本项目不承诺超越前沿模型的能力上限（开源天花板是基座模型，不是架构）；不承诺全自主替代人类；Intent Modeler 依赖可获取的契约输入；v1.0 后渗透能力仍弱于专业人类红队。

## 附录 B：关键基准数据引用规范

引用任何数字时必须标注以下四项，缺一不可：

1. **来源**（论文 arXiv 号 / 官方仓库 / 独立评测）
2. **条件**（是否给定漏洞描述？白盒还是黑盒？是否有人类提示？）
3. **时点**（领域的数字衰减极快）
4. **置信度**（同行评审 / 单一权威来源 / 二手转述）

**反面案例：** "AI 渗透成功率达 87%" —— 缺失全部四项，实际含义是"给定通告描述的理想条件下 GPT-4 对 one-day 漏洞的利用率"，去掉描述即降至 7%，在真实条件下为 13%。
