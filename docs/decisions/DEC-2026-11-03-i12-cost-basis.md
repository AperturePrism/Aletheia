## 1. 问题

`docs/04` §I12 DoD② 原文是：

> **成本较单一前沿模型方案降 ≥ 60%**

**它没有写明"成本"是 token 口径还是货币口径。** 而两种口径的结论相反：

| 口径 | 实测结果 | 是否能达 60% |
|---|---|---|
| token | 最佳 **32.72%**（`tests/i12/last_run.json`，220 次真实调用） | **否，且已证明结构性不可达** |
| 货币 | 尚无数据（缺渠道单价） | 大概率可（token 降 33% + 轻档单价低 5–10 倍） |

在口径未定的情况下，任何"我们降本 X%"的表述都不可核对 ——
换个口径就能得出相反结论，而读者无从判断用的是哪个。

---

## 2. token 口径为什么结构性不可达（证据）

四条原因，均有实测支撑（`tests/i12/README.md`）：

1. **推理 token 是绝对大头**：基线（单一 glm-5.2）中 reasoning 占 **89%**；
2. **思考档是降幅天花板**：planning/analysis 占负载权重 **27%**，
   且**推理保留是质量要求**（`04` §I6 决策①要求规划质量），
   机械档关推理不适用于此 —— 它们贡献约一半 token 且不可动；
3. 机械档关推理**确实生效**（deepseek 关推理后 ≈33 token/调用），
   但机械档基数本就不大，救不动总账；
4. `reasoning_effort=low` **实测无效**（371→372）。

因此 token 口径的 32.72% 是**已测出的上限**，不是"还没优化"。

---

## 3. 决策

**判据定为：**

> **主判据（门禁）：货币口径成本降 ≥ 60%。**
> **副判据（下限）：token 口径降 ≥ 30%，且不得通过降低推理质量换取。**

### 3.1 为什么主判据用货币

"成本"的经济含义是**花了多少钱**，不是"传了多少 token"。
token 是中间量：分级路由之所以能省钱，正是因为轻档单价低 ——
只数 token 会系统性低估这个收益。

### 3.2 为什么保留 token 副判据（≥30%）

三条理由：

1. **它不依赖外部数据**。货币口径要报价单；token 口径用账本就能算。
   把它设为下限，保证"即使没有报价数据，也有一个客观的结构效率指标在守门"。
2. **防"用便宜模型硬压成本"**。只考核货币可能诱导"全换最便宜的模型"，
   token 口径配合质量要求能约束这种倾向。
3. **它已经达成**（32.72% ≥ 30%），因此不会成为新的虚假阻塞项。

### 3.3 为什么不能继续只挂 token 口径的 60%

因为该目标**已被证明不可达**。让一个不可达的判据长期挂在门禁上，
会诱发两类更糟的行为：

* 用 R10 无限期阻塞 I13（项目停滞）；
* 或为"凑绿"而改判据 —— 那正是 `docs/09` §R2 与 `docs/10` §0 明令禁止的。

**把不可达的目标改写为可达且有依据的目标，并留下完整的不可达证明，
比假装它还能达标更诚实。**

### 4.1 缺单价为什么必须报错，而不是按 0 算

按 0 算会让未知模型的成本凭空消失，总额偏小 —— 而那个数字在报告里
看起来完全正常。这是成本模块最危险的失败模式：**它不报错，只是变小**。
因此 `currency_cost()` 在任何一个模型缺价时整体失败，且拒绝"部分核算"
（部分核算的总额同样偏小，却看起来像个完整数字）。
