## 1. 核心开发原则

以下五条是**贯穿所有阶段**的硬约束，任何迭代不得违背。

| # | 原则 | 落地检查 |
|---|---|---|
| **P-1** | **可靠优先于能力** | 每个迭代交付前必须通过长时稳定性测试；崩溃率 > 0 不得进入下一阶段（依据 AIxCC 教训：多数队伍因崩溃丢分） |
| **P-2** | **确定性优先于 LLM** | 能用确定性代码完成的事，禁止交给 LLM。新增 LLM 调用需在 PR 中说明为何无法确定性实现 |
| **P-3** | **证据先于结论** | 任何"发现"在代码路径上必须经由 Evidence Ledger；绕过账本直接产出 finding 的代码路径视为 P0 缺陷 |
| **P-4** | **失败即熔断，不降级** | 范围越界、预算超限、幻觉超阈值 —— 全部 fail-closed，禁止"告警后继续" |
| **P-5** | **可复现即一切** | 任何对外数字必须由 `benchmarks/` 中的脚本产生，第三方可重跑 |

## 2. 阶段与迭代总览

四个阶段、12 个迭代。**阶段划界即能力门禁**：未达门禁不得进入下一阶段。

```
P0 地基（I0–I3）          目标：不会说谎、不会越界、不会崩溃
  I0 仓库骨架与抽象层      ▸ 可编译、可测试、CI 通过
  I1 L0 光谱摄入           ▸ 3 工具适配器 + 解析器覆盖 ≥90%
  I2 L3 证据账本与四道闸门  ▸ 伪造证据注入测试 100% 被拒
  I3 M6 范围内核与隐私网关  ▸ 越界测试 100% fail-closed；抓包零真实值
   ── 门禁：24h 稳定性 + 反幻觉专项全绿 + 越界零漏检 ──

P1 认知层（I4–I6）        目标：记忆不丢、上下文可控、规划可靠
  I4 M2 心智地图与棱镜分解  ▸ 7 类实体 + 多源写入 + 时间版本
  I5 M3 光圈控制           ▸ 跨任务实体召回率 ≥95%；预算约束生效
  I6 M5 编排层             ▸ 任务图 + 确定性求解；对比纯 LLM 逐步决策有可测改善
   ── 门禁：跨会话任务链证据不丢；光圈超预算必然拒绝装配 ──

P2 能力层（I7–I10）       目标：能打、能验证、能给数字
  I7 M4 终止仲裁与状态机补全 ▸ 幻觉终止 0 次通过
  I8 M7 三路融合           ▸ 输出冲突矩阵；对标 VulnHuntr 白盒 / VulHunt 二进制
  I9 M5 后渗透能力扩展      ▸ 内网横向/凭据收集/提权覆盖
  I10 M8 Intent Modeler    ▸ 自建业务逻辑靶场给出首个可复现检出数字
  I11 M9 评测 Harness      ▸ CyBench/CVE-Bench/XBOW 可复现分数
   ── 门禁：公开基准分数产出；业务逻辑数字产出 ──

P3 优化层（I12+）         目标：降本、加固、领域模型
  I12 稳定性与成本治理加固  ▸ 143h 无崩溃；成本较单一大模型降 ≥60%
  I13 轨迹收集与小模型微调  ▸ 高频子任务降本 ≥70%，质量不降
```

## 7. 角色分工建议

按角色而非人头分配，一人可兼多角色。**关键路径（M6→M1→M2→M3→M5→M7→M8）应优先配置。**

| 角色 | 负责模块 | 核心技能 |
|---|---|---|
| **平台工程师** | M6（范围内核/网关/沙箱/可观测/检查点/成本） | Go、Docker、网络、OpenTelemetry |
| **数据工程师** | M1（工具适配/解析器/光谱） + M2（心智地图） | 解析器工程、PostgreSQL、图模型 |
| **AI 工程师** | M3（光圈） + M5（编排） | Agent 设计、上下文工程、规划算法 |
| **反幻觉/验证负责人** | M4（证据账本/闸门/仲裁） | **最关键的独立角色** —— 应独立于产出结论的开发者，形成天然制衡 |
| **安全研究员** | M7（白盒/二进制） + M8（Intent Modeler） | 源码审计、逆向、Web 业务逻辑 |
| **评测工程师** | M9（Harness/靶场/指标） | 基准搭建、统计、可复现性工程 |
| **前端工程师** | WebUI 全部页面（见 `06` §6）+ 与后端共同维护 Protobuf 契约 | React/TypeScript、数据可视化、图渲染 |

**岗位设计要点： M4 负责人必须独立于 M3/M5 负责人。** 让产出结论的人同时校验结论，会使反幻觉机制失效——这是制度设计而非人力问题。

**人力提示：** 若人力有限，WebUI 可按 `06` §6.1 的优先级分批交付。**但三个核心视图（证据链 / 光圈上下文 / 冲突矩阵）不可省略** —— 它们承载的正是本项目的差异化。
