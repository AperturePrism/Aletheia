# AI 渗透测试开源项目全景调研报告

> 调研时点：2026-09-24
> 调研范围：全球公开开源项目（含学术原型、工程化平台、MCP 工具层、白盒审计、DARPA AIxCC 竞赛系统）
> 数据来源：GitHub 仓库文档、arXiv 论文、独立评测博客、厂商公开数据
> 置信度约定：**A** = 同行评审论文或多源交叉验证；**B** = 单一权威来源（官方仓库/厂商博客）；**C** = 二手转述或内容农场，需以仓库为准

## 0. 核心结论（先读这一段）

**结论一：开源 AI 渗透的分水岭不是"能不能做"，而是"证据能不能立住"。**

能力天花板已由厂商模型决定。2026 年 4 月 Anthropic 的 Mythos Preview 在所有主流操作系统与浏览器中发现数千个高危漏洞（含 OpenBSD 存在 27 年、FFmpeg 存在 16 年的漏洞），并因此被限制发布（仅 12 家 Glasswing 伙伴 + 40 余家关键基础设施组织可用）【B】。这意味着**开源项目的架构优劣已不再是主要瓶颈，能拿到的基座模型才是**。

**结论二：实验室数据与真实环境之间存在断崖式落差，这是全行业最容易被误读的数字。**

| 条件 | GPT-4 表现 | 说明 |
|---|---|---|
| 给定 CVE 通告描述的 one-day 漏洞 | **87%** 可利用 | Fang et al. 2024，UIUC【A】 |
| 去掉通告描述 | **7%** | 同一实验，唯一变量【A】 |
| CVE-Bench（模拟真实条件的 40 个严重漏洞） | **13%**（SOTA） | ICML 2025 Spotlight【A】 |
| HackTheBox 困难靶机 | **≈0%** | 所有被测模型【A】 |
| AutoPenBench 全自主 | **21%** | 有人类提示时升至 **64%**【A】 |
| PentestEval 端到端流水线 | **31%** | 9 个 LLM 中最好成绩；论文结论是"全自主 agent 几乎完全失败"【A】 |

**记住这句：87% 是理想条件下的天花板，不是实用能力的地板。**

**结论三：多智能体架构稳定胜出，但胜出幅度被高估。**

- HPTSA 层级团队在 14 个真实漏洞上比单 agent 提升 **4.3 倍**（42% pass@5 / 18% pass@1）【A】
- D-CIPHER 比单 agent 基线多解决 **65%** 的 MITRE ATT&CK 技术【A】
- 但 **PentestEval 的结论是标准 ReAct 循环常已足够，甚至优于复杂的多 agent 架构**——多智能体不是免费的午餐【A】

**结论四：真正的护城河是业务逻辑，而目前没有任何开源 agent 能可靠覆盖。**

ARTEMIS 研究（2025-12）在 8,000 台主机的真实企业网络中对战 10 名人类渗透测试员：AI 排名第 2，成功率 82%，击败了其中 9 名，成本约 **$18/小时**（人类 $60+/小时）。但论文明确指出：**关键 Web 漏洞中约 70% 属于业务逻辑缺陷，当前没有任何自主 agent 能可靠检测**。人类唯一的、也是决定性的优势在这里【A】。

**结论五：领域微调的中等规模模型 > 通用大模型。**

xOffense 用微调后的 **Qwen3-32B** 取得 **79.17%** 子任务完成率，超过运行于更大前沿模型的 VulnBot 与 PentestGPT【A】。CIPHER 用更小的领域模型超过 Llama 3 70B【A】。**领域适配的重要性高于参数规模。**

## 1. 调研方法与分类框架

### 1.1 什么叫"AI 渗透系统"

判定标准有三条，缺一不可：

1. 用大语言模型做**推理**
2. **实际执行**攻击性工具（而非仅建议命令）
3. 对目标产出**可报告的结论**

据此排除：纯扫描器（Nessus/OpenVAS）、固定剧本的 BAS 产品（CALDERA 类）、纯提示词插件。

### 1.2 六大架构范式

从 39+ 个开源项目中归纳出的六种架构模式，每种都有明确的取舍：

| # | 范式 | 核心机制 | 代表项目 | 主要代价 |
|---|---|---|---|---|
| 1 | 单 Agent（ReAct 循环） | 一个 LLM 循环推理-行动-观察 | PentestGPT、hackingBuddyGPT、AutoPentest、RapidPen | 上下文窗口耗尽即"失忆" |
| 2 | 多 Agent 规划-执行分离 | Planner 决策、Executor 执行，上下文隔离 | VulnBot、CHECKMATE、HPTSA | 通信开销、级联失败 |
| 3 | 多 Agent 专精角色 | 每 agent 固定领域，并行共享状态 | PentAGI、Zen-AI-Pentest、BlacksmithAI | 编排脆弱、并行成本高 |
| 4 | 动态 Swarm | agent 数量按攻击面动态伸缩 | Pentest Swarm AI、D-CIPHER | 状态一致性难保证 |
| 5 | MCP 工具层 | 把工具包成 MCP server，推理交客户端 | HexStrike AI、AutoPentest-AI、PentestMCP | 推理质量完全外包 |
| 6 | Harness 原生（Claude Code 等） | 用 markdown skill 配置现成 agent 运行时 | Raptor、Transilience、Claude Bug Bounty | 锁定单一生态 |

**范式选择的工程判断：**

- **范式 1** 适合学习与调试。hackingBuddyGPT 的基线示例约 50 行 Python，是理解 ReAct 渗透循环的最佳起点。它的天花板也很明确——PentestEval 判定该范式"端到端几乎完全失败"。
- **范式 2 是被论文验证的最优性价比。** CHECKMATE 的方法尤其值得学习：**不让 LLM 做长期规划，而是让 LLM 生成 PDDL 领域描述，交给 1970 年代的经典规划器求解**。结果比 Claude Code 原生 agent 成功率高出 20%+，同时快 50%+、便宜 50%+。核心教训：**LLM 不擅长的长程规划，交给算法。**
- **范式 3/4** 工程复杂度最高，但也是 PentAGI、Strix 这类平台型项目选择的路线。
- **范式 5** 是 2026 年增长最快的形态，因为构建成本极低（本质是工具适配层），且天然嵌入现有工作流。代价是**推理质量完全取决于客户端 LLM，MCP 层无法补偿**。
- **范式 6** 迭代最快（改行为 = 改一个 .md 文件），但锁定生态。

### 1.3 五层成熟度分级（按文档完备度与验证深度）

| Tier | 定义 | 数量 | 适用场景 |
|---|---|---|---|
| T1 | 主要自主 agent（星标高、有公开基准或生产案例） | 6 | 接近生产的评估 |
| T2 | 专精与新兴 agent | 9 | 研究、实验、细分场景 |
| T3 | MCP 化工具 | 6 | 追求迭代速度、模型无关 |
| T4 | 漏洞发现工具（源码/二进制） | 4 | 0day 挖掘 |
| T5 | DARPA AIxCC 开源 CRS | 7 | 参考实现、学术验证 |

**注意：GitHub 星标不是质量信号，只是可见度信号。** 搜索中出现了明显冲突的星标数据（某中文源称 Strix 57.8k star，另一独立分析称 PentAGI 约 14,700 star），此类数字一律以仓库实时数据为准，本报告不作为论证依据。

| 42-b3yond-6ug | 6th | BugBuster | **实用主义**：传统技术为核心，LLM 仅辅助 | 传统模糊测试与程序分析为主，LLM 做种子生成等辅助；**"超级补丁"可同时修复多个关联错误** |
| SIFT 等 | 7th | Lacrosse | DSPy 驱动的多 LLM 工作流 | 基于 Lisp 任务分发器协调多 agent；DSPy 管理多模型并行/降级；补丁失败反馈优化漏洞特征 |

**AIxCC 的四条核心教训（SoK 论文 arXiv:2602.07666）【A】：**

1. **稳定性与准确率是制胜关键** — 冠军凭全阶段持续运行取胜，精度惩罚足以让第二名掉到第三名
2. **技术先进 ≠ 工程可靠** — 约半数漏洞基础技术即可解决，但多数队伍因系统崩溃、配置错误等工程问题丢分
3. **LLM 突破了传统模糊测试的局限** — CRS 发现 22 个并行模糊测试无法识别的漏洞，尤其擅长复杂语法输入、逻辑约束破解
4. **补丁准确率仍是最大挑战** — 主流队伍补丁准确率在 23%–84% 之间；最优者靠严格过滤才达 100%

**四大标准提交物（对设计新系统极有参考价值）：**

| 提交物 | 含义 | 分值 |
|---|---|---|
| PoV（漏洞证明） | 能触发漏洞异常执行的输入 | 2 分 / 迟交 -1 分 |
| Patch（补丁） | 修复且不破坏功能的代码 | **6 分** / 迟交 -3 分（权重最高） |
| SARIF 评估 | 判断静态告警真/假阳性 | 1 分 / 0.5 分（权重最低） |
| Bundle（漏洞关联） | 把同一漏洞的 PoV/Patch/SARIF 归组 | ±7 分（**错误关联重罚**） |

## 4. 共性缺陷清单（"糟粕"靶点）

以下 14 项是全行业（含学术原型与商业产品）反复暴露的问题，按严重度排序。**这是新项目必须逐条给出对策的地方。**

### 4.1 认知类缺陷

| # | 缺陷 | 证据 | 严重度 |
|---|---|---|---|
| **D1** | **幻觉式成功（Hallucinated Success）** | 实测案例：agent 报告"23/23 端口攻破、全部 root"，实际获 shell 数 = **0**。根因是验证器用字符串匹配判定成功——`searchsploit` 每次搜索都会打印含 "Shellcodes" 的头部，任何回显 "login:" 的服务都被判为已攻破。改为强制证据正则（`uid=\d+.*gid=\d+`、`root@[\w.-]+:[~/]`）后，成功率从 23 掉到 **3**，但这 3 个是真的【B】 | 致命 |
| **D2** | **自言自语（Soliloquizing）** | EnIGMA 论文（ICML 2025）记录：agent 停止真正执行命令，开始**想象命令输出**，在虚构结果上继续推理，陷入自我指涉循环。表现上像在工作，实际什么都没做【A】 | 致命 |
| **D3** | **Flag 幻觉** | "Hackers or Hallucinators?" 大规模分析：agent 发现一段 Base64 或随机哈希就断定是 flag，**幻觉成功后立即提前终止会话**。几乎所有框架都有此问题，**换更强的模型（如 GPT-4）也无法解决**【A】 | 致命 |
| **D4** | **上下文失忆** | 单次 nmap 输出可达数千行，撑爆上下文后早期发现被挤出。实测：agent 发现线索（隐藏 API 参数）后被另一端点分心，**20 步后完全遗忘该线索**。缺少人类渗透测试员笔记式的持久结构化心智地图【A/B】 | 高 |

### 4.2 能力类缺陷

| # | 缺陷 | 证据 | 严重度 |
|---|---|---|---|
| **D5** | **业务逻辑盲区** | ARTEMIS：**约 70% 的关键 Web 漏洞是业务逻辑缺陷**，当前无任何自主 agent 能可靠检测。需要理解"应用应该做什么"，而不只是"它做了什么"【A】 | 高（护城河） |
| **D6** | **多步链式能力弱** | 链式漏洞任务成功率仅约 **16%**。agent 常卡在无法把侦察阶段的发现（密码、会话 cookie）传递到利用阶段【A】 | 高 |
| **D7** | **多会话状态混淆** | IDOR 类漏洞需要同时持有 A/B 两个账号状态。实测 agent 频繁混淆两个会话的 cookie，从错误上下文执行动作，最终判定"漏洞不存在"（假阴性）【B】 | 高 |
| **D8** | **RAG 负收益** | 论文发现外部知识库**经常产生负回报**。低精度检索会引入幻觉，必须"质量优于数量"【A】 | 中 |

### 4.3 工程类缺陷

| # | 缺陷 | 证据 | 严重度 |
|---|---|---|---|
| **D9** | **工具调用契约脆弱** | HexStrike 独立实测：httpx 命令参数错误导致完全失败；参数错误导致**扫描了完全超出范围的目标**；部分工具直接超时；大目标下客户端挂死。另一实测记录了 schema 不匹配（模型传 `{"query":...}`，工具要 `{"keyword":...}`，MCP 层静默拒绝）、**ANSI 转义污染**（把 `exploit/unix/\x1b[45mftp\x1b[0m/vsftpd_234` 当成模块路径）、版本串混淆（nmap 报 "2 (RPC #100000)" 被当成产品名传给 Metasploit）【B】 | 高 |
| **D10** | **工程可靠性拖累技术能力** | AIxCC SoK：约半数漏洞基础技术即可解决，但**多数队伍因系统崩溃、配置错误丢分**。"技术先进与工程可靠是两回事"【A】 | 高 |
| **D11** | **无范围硬约束** | 三大失败模式之一：范围控制弱 → agent 触碰从未纳入演练的系统/账号/工具。工具层必须限制目标、动作与工具使用，**而不只是限制最终报告**【B】 | 高 |
| **D12** | **编排脆弱 + 级联失败** | 多 agent 专精架构的通病：侦察 agent 漏掉一个开放服务，下游永远不会测试它【A】 | 中 |
| **D13** | **过度自信与信号/噪声混淆** | 团队把"产出量"当"价值"，把看似合理的未验证结果当成 findings。agent 生成的扫描结果在云/API/身份密集环境中尤其"看起来很棒"，但**高产出不等于高信号**【B】 | 中 |
| **D14** | **可观测性与证据链缺失** | 多数项目无法回答"agent 为什么这么做""这个结论的证据是什么"。PentAGI 补了 Langfuse/OTel，CAI 补了 OTel+Phoenix，但这是少数派【B】 | 中 |

### 4.4 治理与安全类缺陷

| # | 缺陷 | 证据 |
|---|---|---|
| **D15** | **数据主权外泄** | 自主 agent 一旦把真实 IP、主机名、凭据、内部路径发给云端模型，敏感信息即离域。对受监管/国防团队这是**一票否决**的问题。Darkmoon 的 Privacy Gateway 是少数正面解法 |
| **D16** | **被武器化滥用** | HexStrike AI 于 2026 年 8 月被报道用于**自动化利用某 Citrix 漏洞**，攻击者利用它做规模化自动攻击。开源 + Kali 工具链 + 自主规划同时降低了专业红队门槛和滥用门槛 |
| **D17** | **生态锁定** | Claude Code 原生范式（范式 6）迭代最快，但完全锁定单一供应商生态 |
| **D18** | **遥测默认开启** | PentestGPT 默认向 Langfuse 发送匿名使用数据，需命令行参数或环境变量显式关闭 |
| **D19** | **默认配置不安全** | PentAGI 默认口令 + 自签证书，未修改配置会把目标信息泄露给模型供应商与搜索引擎 |
| **D20** | **贡献者集中（bus factor）** | PentAGI 星标很高但核心提交高度集中于创始人；HexStrike 代码提交停滞、issue 积压 |

## 6. 结论：六个未被解决的空白

调研项目总数 39+，论文 40+，基准 8 个，但以下空白**全行业无一填满**。这是新项目的立项依据。

| # | 空白 | 现状 | 机会 |
|---|---|---|---|
| **G1** | **可证明性 / 证据链强制化** | 少数项目（Strix、Shannon）要求 PoC，但**无任何项目把"证据链"作为一等公民数据结构**，多数仍靠字符串匹配判定成功 | 把"证据"作为核心数据结构，所有结论必须挂载可复现的 PoC 与可追溯的执行证据 |
| **G2** | **业务逻辑理解** | 70% 关键漏洞在业务逻辑，agent 全部失明 | 引入应用意图建模（从规格/流量/源码推断"应该做什么"），做差异性检测 |
| **G3** | **结构化持久记忆** | PentAGI 用 pgvector + 图谱（做得最好），但仍是"检索式"而非"心智地图式"；多数项目就是上下文窗口 | 资产-服务-凭据-漏洞-路径的**图结构心智地图**，跨会话持久，主动推送而非被动检索 |
| **G4** | **跨范式融合** | 黑盒 agent、白盒审计、二进制分析三条线**完全割裂**，各做各的 | 统一编排：黑盒给出攻击面，白盒给出代码级根因，二进制给出闭源目标覆盖，三路交叉验证降误报 |
| **G5** | **成本硬治理** | 多数项目对 token 消耗无硬约束，"死循环烧 token"是普遍现象 | 预算作为一等约束（像 AIxCC 每队固定算力/API 额度一样），超预算即熔断 |
| **G6** | **数据主权** | 仅 Darkmoon 提供了确定性脱敏网关，其余项目默认把敏感值送云端 | 隐私网关内建为默认（而非可选）路径，配合本地模型降级策略 |

**次要空白：** 后渗透与内网横向（海外项目普遍薄弱）、人机协同粒度控制、攻击路径分支管理（仅 pentestagent 有 rewind/fork）、统一评测 harness、中文生态与国内合规适配。
