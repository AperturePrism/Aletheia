### 本次新踩的环境坑（重要）

**`bash` 解析到 WindowsApps 的 WSL stub，会让所有调用 bash 的测试失败。**

症状：`pytest` 有 7 个用例失败，错误形如

```
/bin/bash: D:ProjectAperturePrism-AI渗透scriptscheck-no-bypass.sh: No such file or directory
```

根因：`C:\Users\<user>\AppData\Local\Microsoft\WindowsApps\bash.exe` 是
WSL 转发 stub，它把 Windows 路径的 `\` 当转义符吃掉，且不处理非 ASCII
路径（本仓库路径含中文）。

**解法**：把 Git Bash 放到 PATH 最前。

```powershell
$env:PATH = "C:\Program Files\Git\bin;" + $env:PATH
```

之后 `pytest` 为 `110 passed, 1 skipped`。

**这不是代码缺陷，是本机 PATH 顺序问题。** 但值得写进文档 —— 因为
Makefile 与 `docs/01` 反复强调"Windows（Git Bash）与 Linux/macOS 行为
一致"，而实际只要 PATH 里有 WindowsApps stub 就会踩到。

### 本次引入的依赖（docs/09 §5 #3 四项）

| 依赖 | 版本 | 许可 | 用途 | 替代方案 |
|---|---|---|---|---|
| `modernc.org/sqlite` | v1.34.5 | BSD-3 | 单一属性图存储 | `mattn/go-sqlite3`（需 cgo，与"无 C 工具链可构建"冲突，不采纳） |
| `github.com/improbable-eng/grpc-web` | v0.15.0 | Apache-2.0 | 浏览器 gRPC-Web 桥接 | `connect-go`（能力等价但需重写前端 transport，且引入第二套 RPC 风格，与"契约同源"目标无益） |

**版本约束注意**：`modernc.org/sqlite` 的最新版要求 Go ≥ 1.26，会把
`go.mod` 的 `go` 指令顶上去，与 CI 的 `GO_VERSION: "1.24"` 冲突。
本次固定在 v1.34.5 并显式 pin 了 `golang.org/x/sys@v0.29.0`。
**升级该依赖时务必检查 `go.mod` 的 `go` 指令是否仍为 1.24。**
