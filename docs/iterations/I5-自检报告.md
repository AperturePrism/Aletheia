## 4. 自检的三个强制时点（`docs/10` §6）

### 时点 1：写完测试后、跑测试前 —— "这些断言真的在验证功能吗"

**召回率测试是本迭代最关键的断言，逐条自问：**

- 它**不是**恒真断言：断言的是"任务 A 写入的 ENDPOINT 是否出现在
  任务 B 的装配结果里"，且任务 B 的 `focus_hint` **只含它自己知道的
  主机名**（不含实体 ID、不含端点路径）。若把 hint 直接当实体 ID 传给
  图，结果为 0 —— 本测试第一次运行就报出 `0/100 = 0.0%`，精确定位了
  一个真实缺陷（详见 `I5-交接.md` §7 注意事项 1）。
- `TestAssembleNeverExceedsBudget` 不只断言 `estimated ≤ budget`，
  还**重新计算**一次估算值并与报告值对比（防止估算器与判据漂移成
  两份实现）。
- `TestDowngradeNarrowsAndIsRecorded` 断言"要么降档、要么有显式省略
  记录"—— 若两者都没有，说明存在静默截断。
