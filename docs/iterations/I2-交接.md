**关键设计决策**（详见代码注释）：
1. 闸门语义精确化：G-3 失败封顶 CANDIDATE（弱证据是待补强不是已证伪），
   REJECTED 仅 G-2 失败；G-1 失败不产 Finding（D2 语义）。
2. 幂等 = 重放：同 ID 内容一致（代回账本赋权字段重算哈希）才返回既有；
   内容不同是伪造信号。
3. append 不修改调用方对象（重放为纯函数行为）。
4. 比例熔断最小样本量 10（小样本下 1/1=100% 会压过 agent 阈值语义）。
5. 归因语义（05 §1.3 精确化）：冲突断言自身记 HYPOTHESIS；既有正确引用者
   状态保留但标 needs_review（保守复核面）。
6. ts-proto 不输出 definition 常量 → 手写 definition（编解码全部取自生成物，
   方法集合有运行期断言 + 契约测试兜底）。

## 6. 新踩的坑（I2 新增 2 条）

1. **Python protobuf 枚举常量无类型前缀**（`pb.EVIDENCE_INVALID` 而非
   Go 风格 `pb.ErrorCode_EVIDENCE_INVALID`）—— 双语言项目里混用会
   AttributeError。同理 `pb.FindingStatus.Name(x)` 接受 int 返回 str，
   状态比较要统一 int/str 形态。
2. **ts-proto v2 的 `encode()` 返回 BinaryWriter**，不是 Uint8Array ——
   调 `.finish()` 收字节；其 `MessageFns.encode` 的默认 writer 参数让它
   看起来像可选零参调用，注意别在 definition 里误包。
