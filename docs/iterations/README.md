# 开发交接文档 · 模板与填写规范

> 用途：每个任务 / 迭代结束时产出，交给下一位开发者（**不假定使用 Claude Code**）。
> 上游依据：`09-开发交接说明-致ClaudeCode.md` §10（完成一个迭代要交什么）、
> `10-自检与偏差检查清单.md` §3（十类跑偏模式）。
>
> **填写铁律**（来自 `docs/10` §0）：
> 能用命令验证的项，**必须附命令 + 原始输出**，不接受"已检查"这类无证据结论。
> 无法用命令验证的，必须显式标注「仅人工判断」。
>
> **本文件是模板。实际交接文档以 `iterations/I{n}-交接.md` 命名，一份迭代一份。**

---

## 为什么要这个文档

`docs/09` 第 10 节规定完成一个迭代要交 9 项东西，其中第 3、4、9 项是硬要求。
这个模板把那 9 项变成可填写的固定结构，并加了两样 `09` 没明说但必需的内容：

1. **环境与工具链的实际状态** —— 换个机器接手的人第一件事是装环境，
   而"这台机器缺 make、缺 C 编译器"这类事实只在当时的人脑子里。
2. **下次开工的第一条命令** —— 消除"打开仓库不知道从哪开始"的空转。

**不假定工具。** 每一步都给出可直接执行的命令，而不是描述某个工具的操作。
接手方用 Claude Code / Cursor / 直接手写，都能照着做。

## 与其他文档的关系

| 文档 | 关系 |
|---|---|
| `iterations/I{n}-自检报告.md` | 自检报告是**依据**（红线逐条核查的原始记录）；交接文档是**摘要 + 行动指引** |
| `04-开发总纲` | 交接文档第 5 节要回填到 `04` 的对应迭代（活文档） |
| `CHANGELOG.md` | 变更记录按 Keep a Changelog 组织；交接文档不做逐条变更清单 |

**维护规则**：新增迭代时复制本模板，填完后的文件以 `iterations/I{n}-交接.md` 命名。
本模板自身演进时，在 `CHANGELOG.md` 记一条 `Changed`。
