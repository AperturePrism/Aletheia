## 5. 自检的三个强制时点（`docs/10` §6）

### 时点 1：写完测试后、跑测试前 —— "这些断言真的在验证功能吗"

**假阴性用例（`LEGITIMATE_CASES`）在本迭代发挥了决定性作用 ——
它们抓到了两个真实缺陷。** 这正是 `docs/10` §0 强调"绿灯替代有效"的
正面案例：若只写"该拒的都拒了"的用例，这两个 bug 会一直存在，
且表现为**真实场景下 agent 永远无法合法终止**。

**缺陷 1：`root@target:~#` 被判为幻觉**

```
E  AssertionError: LEGITIMATE TERMINATION REFUSED [shell-root-prompt]:
   'root@target:~# ' — reason=4,
   checks=('G-hallucination: SUSPECT — claimed achievement is only 2 chars ...',)
```

根因：裸 token 提取逻辑按 `:` 切分，把 `root@target:~#` 切成 `~#`
（2 字符）→ 落入"信息量不足"分支。**一个真实的 root shell 达成物被
当成幻觉拒掉。**

修复：新增 `_ACCESS_INDICATOR` 优先判定（`uid=` / `gid=` / `root@` /
提示符），并把 `:` 切分限制在"前缀是短标签"时才执行（避免切坏 URL）。

**缺陷 2：`aGVsbG8gd29ybGQh`（16 字符 base64）未被识别为 base64**

```
E  AssertionError: aGVsbG8gd29ybGQh
   assert False = HallucinationSignal(suspected=False, reason='').suspected
```

根因：`_B64_TOKEN` 的长度下限是 20，而该串长 16 → 落进"长度不足"分支。
两者都拒绝，但**原因不同，而原因要写进审计**（agent 据此修正行为）。
修复：下限降到 16。

**这两个缺陷都不是"测试写错了"** —— 是实现真的会在真实场景下拒掉
合法的 root shell 终止请求。假阴性用例的价值在此得到验证。

**`test_check_hallucination_runs_before_evidence` 的断言强度：**
它断言早退时 `G-evidence` **不出现**在 checks 里 —— 这直接锁死了
"幻觉检测先于证据校验"这一结构性防线（防止精心构造的证据链为幻觉
背书）。

**`test_zero_fabricated_approved_aggregate` 的断言强度：**
它逐组调用并断言 `approved == []`。若某组用例被批准，失败信息会列出
具体是哪几组 —— 不是笼统的"有失败"。

## 6. 口径完整性的诚实声明（本次自检的重点）

`M4 §4.5` 第 ③ 道校验原文是「证据是否通过**全部四道闸门**」。
但 **G-4 独立复现未交付**（T4.9，需 docker 容器快照），因此
`_evidence_gate_passed()` 实际口径是：

| 闸门 | 是否参与 | 如何判定 |
|---|---|---|
| G-1 执行绑定 | ✅ | 入库时 `Ledger.append` 强制验签（无旁路） |
| G-2 断言校验 | ✅ | 证据存在即被引用过 |
| G-3 证据强度 | ✅ | 该证据的 exec 上有**被接受的**副作用观测 |
| **G-4 独立复现** | ❌ **未参与** | **未交付** |

**当前"四道闸门"实为三道。** 已在 `arbiter.py` 的
`_evidence_gate_passed` docstring 与 `I7-交接.md` §5 D-3 显式登记，
不得让调用方以为四道都过了。

按 `docs/10` §0（「无法验证的项必须显式声明『无法验证』，不能让
『没查』伪装成『没问题』」），这条必须写明而不是留在代码里。
