### 已知的环境坑

这些是本次开发中**真实踩到**的，每条给出症状与解法。

| # | 症状 | 根因 | 解法 |
|---|---|---|---|
| 1 | `make: *** Makefile:157: *** target pattern contains no '%'` 或 `\: -c: line 5: unexpected EOF while looking for matching '"'` | Makefile 的 recipe 用 `\` 续接多行 shell，Git Bash 对 if/else 与 heredoc 的处理不可靠 | **已修**：所有复杂逻辑移到 `scripts/*.sh`。新增门禁时同样 Extracted 成脚本，不要写进 recipe |
| 2 | `go: -race requires cgo; enable cgo by setting CGO_ENABLED=1` | 本机无 C 编译器 | 用 `GO_TEST_RACE=0`（默认）跳过，或装 MinGW。**没有删掉 race 检测**，只是做成显式开关 |
| 3 | `go test ./...` 输出多出一行 `web/node_modules/flatted/golang/pkg/flatted` | 那个第三方包没有自己的 `go.mod`，被算进本模块 | **已修**：所有 go 命令限定 `./cmd/... ./core/...`（Makefile 的 `GO_PKGS`）。新增 go 命令时沿用 |
| 4 | `npm install` 后 `buf` 命令不存在 | 新版 npm 默认拦 postinstall（buf 要下载平台二进制） | `npm install-scripts approve @bufbuild/buf && npm rebuild @bufbuild/buf`。同理 `protobufjs`、`esbuild` 在 `web/` 下也要 |
| 5 | pytest 读 subprocess 输出时 `UnicodeDecodeError: 'gbk' codec` | 脚本输出含 ANSI 颜色码，Windows 默认 GBK 解不开 | subprocess 调用加 `encoding="utf-8", errors="replace"`，并且**子进程加 `-X utf8`**（只设 `encoding=` 不够 —— 子进程自己按 GBK 编码输出） |
| 6 | `go mod tidy` 会把 `go.mod` 里的依赖注释全部删掉 | tidy 重写整个 require 块 | tidy 之后手工补回注释。**不要跳过补注释** —— `09` §5 #3 要求每个依赖说明四项 |
| 7 | **CI 首跑 4 个 job 失败**：`eslint: not found` + 大量 `TS2307 Cannot find module 'react-router-dom'` + `.venv/bin/python: No such file or directory` | `make env` 只装根 `package.json` 的依赖（buf），**从没装 `web/` 的前端依赖**；且 `.venv/bin/python` 是 Linux 路径写法 | **已修**：`make env` 拆为 `env-web` + `env-root`；CI 改用 `make test-python PYTEST_ARGS=...` 让 Makefile 按平台选 Python 路径。**教训：本地全绿不代表 CI 能跑 —— 干净环境是唯一诚实的验证** |
| 8 | `ruff format` 重排 `docs/` 下 markdown 的代码块 | ruff 会把 md 里的 ```python 代码块当源文件 scan + format | **已修**：`pyproject.toml` exclude `docs/**/*.md`。改后仅 10 个真实 `.py` 参与检查 |

### 本次开发中发现并修复的三个真实缺陷

都有测试锁定了，列出以备接手方理解相关测试为何存在：

1. `core/checkpoint` 的 blob shard 子目录未创建 → 写 blob 报
   `cannot find the path specified`。修：`os.MkdirAll` shard 目录。
2. `core/checkpoint.List` 用纳秒级时间戳排序 → 同批次创建的 checkpoint 顺序不确定，

   `fmt.Sprintf`**。这个缺陷是**被 `tests/test_security_scan.py` 的变异验证当场抓到的** ——
   只跑扫描脚本发现不了它（单侧漏检在双语言项目里是高危模式）。
