### D-3 详解（必须让接手方知道）

`05 §6.2` 的 OrchestratorService 只有：`Plan`（写入）、`NextReady`
（返回任务 ID + 阻塞原因）、`ReportTaskResult`、`Refine`、`Checkpoint`、
`Rewind`、`Fork`。**没有读取完整图的 RPC**。

这直接影响 06 页面 7（决策队列）：它需要任务的角色、证据、失败记录
才能渲染 06 §7.1 要求的四要素卡片，而这些都不在 `blocked_reasons` 里。

按 `docs/09` R1（「不得修改 05 契约，任何变更须走 `contract:` PR 且需
双人 review」），本次**没有**自造 RPC、**没有**改 proto，而是：

1. 改用 `NextReady.blocked_reasons`（`map<task_id, reason>`）—— 这是
   契约内可得的最大信息量，恰好能表达"每个任务当前为什么不能跑"；
2. 在页面上**显式声明缺口**（琥珀色区块 + 指向正确的 `contract:` 流程）；
3. 未知字段**留空并说明**（角色显示 "—"、证据摘要写明"不在
   `blocked_reasons` 中"），**不填占位文本、不编造置信度**。

**待办**：提一个 `contract:` PR 新增只读的 `GetGraph(session_id) → TaskGraph`。
在此之前决策队列只能呈现部分信息 —— 这是契约限制，不是实现偷懒。

## 6. 已知缺口与风险

| 缺口 | 影响 | 何时必须解决 | 阻塞谁 |
|---|---|---|---|
| Agent 池（T5.5/T5.6） | 无法真正执行任务 | 需真实端到端渗透时 | 阻塞 I9 |
| Planner LLM prompt（T5.2） | 图须由外部生成后传入 `Plan` | 同上 | 同上 |
| 模型分级路由（T5.10） | 无成本优化 | I12 | 不阻塞 |
| 熔断 2/8 类未实现 | "总运行时长""单任务 token"无保护 | I12 | 不阻塞 |
| **契约缺 GetGraph RPC** | 决策队列信息不完整 | I6 收口 | 阻塞决策队列的完整形态 |
| 检查点不持久化 | 跨进程无法恢复 | 需要长任务恢复时 | 不阻塞 |

**为什么把"确定性骨架"与"LLM 接线"分开**：M5 §2 的核心决策是
「不让 LLM 做长程规划」。该决策的价值体现在"确定性部分可被独立验证"
上 —— 混在一个提交里会让「零 LLM」这条契约无法被清晰断言。
这也是 `TestNoLLMClientInPackage` 能作为静态检查生效的前提。
