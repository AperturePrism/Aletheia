## 4. 自检的三个强制时点（`docs/10` §6）

### 时点 1：写完测试后、跑测试前 —— "这些断言真的在验证功能吗"

**`TestNoLLMClientInPackage` 是本迭代最关键的断言，逐条自问：**

- 它**不是**恒真断言：带 vacuity 防护 —— 若扫描到 0 个源文件即
  `t.Fatal`。这防止"路径写错导致永远通过"。
- 它**必须是静态检查**而非运行时断言：一旦引入了 LLM 依赖，运行时测试
  无法发现（测试可以不触发那条分支）。模块规格 §6 明确要求静态检查。

**★ 自检中发现并修掉了该检查自身的一个真实漏洞（重要）：**

初版检查的是**调用形态**（`"http.Get("`、`"http.Post("`）。自检时按
`docs/10` §0「绿灯替代有效」的要求做了变异测试 —— 在包内注入：

```go
import "net/http"
var _ = http.Get          // 方法值，无括号
```

结果**检查未报警，测试通过**。根因：`"http.Get("` 要求带左括号，
而 `http.Get`（方法值）、`http.DefaultClient.Do(..)` 等变体都绕得过。
**该检查当时是无效的。**

修复：判据从"调用形态"改为**包路径**（`"net/http"`、`"os/exec"`、
`"database/sql"` 等）。包路径是"具备 IO 能力"的**必要条件**，
无法在不被察觉的情况下引入。同时把 LLM 依赖匹配从裸子串改为
import 字面量前缀（裸 `"llm"` 会误命中含该片段的合法路径）。

修复后的变异验证（原始输出）：

```
=== 基线（应通过）===
scanned 4 source files; no IO package and no LLM dependency found
--- PASS: TestNoLLMClientInPackage

=== 变异：import net/http（方法值形态）===
--- FAIL: TestNoLLMClientInPackage
    planner.go: imports "net/http" — the deterministic planner performs no IO
FAIL

=== 恢复后 ===
ok  	github.com/AperturePrism/aleth/core/orchestrate	0.167s
```

**这条记录本身就是 `docs/10` §0「绿灯替代有效」的实例**：
初版检查有绿灯，但它不有效。若无变异测试，这个漏洞会一直存在 ——
而它守护的恰恰是"零 LLM"这条契约硬约束。

**`TestRefineProducesDistinctActionsPerFailureType` 的断言强度：**

它断言的是"六类失败产出的 guidance **两两不同**"。这条断言直接对应
`M5` §4.2 的核心主张——"与简单重试的区别"。若六类返回同一句话，
测试立刻失败。

**`TestCircuitScopeViolationTerminatesFirst` 的断言强度：**

它构造**四个熔断条件同时满足**的状态（越界 + 预算耗尽 + 幻觉超限 +
无进展），断言结果仍是 `ActionTerminateSession`。若评估顺序写反，
测试失败。
