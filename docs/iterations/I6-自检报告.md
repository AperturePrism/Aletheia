### 时点 1：写完测试后、跑测试前 —— "这些断言真的在验证功能吗"

**`TestNoLLMClientInPackage`（I6 的第一版，`b94aa62`）：**

初版检查**调用形态**（`"http.Get("`）。自检时做变异测试 —— 注入

```go
import "net/http"
var _ = http.Get          // 方法值，无括号
```

**检查未报警，测试通过。根因：`"http.Get("` 要求带左括号。该检查当时无效。**

修复：判据改为**包路径**（`"net/http"` / `"os/exec"` / `"database/sql"`），
并把 LLM 依赖匹配从裸子串改为 import 字面量前缀。修复后变异验证：

```
基线     → scanned 4 source files; no IO package and no LLM dependency found (PASS)
注入变异 → planner.go: imports "net/http" (FAIL)
恢复后   → ok
```

**这条记录本身就是 `docs/10` §0「绿灯替代有效」的实例** —— 初版有绿灯
但它不有效。已写入 `I6-自检报告.md`（本文件前身）§4 与提交说明。

**`TestRefineProducesDistinctActionsPerFailureType`：** 断言六类失败的
guidance **两两不同**。若都返回同一句就退化成简单重试 —— 正是 `M5`
§4.2 要避免的。这条断言直接对应规格的核心主张。

**`TestCircuitScopeViolationTerminatesFirst`：** 构造**四个熔断条件
同时满足**的状态，断言结果仍是 `ActionTerminateSession`。若评估顺序
写反，测试失败。

**`TestReserveRefusalIsBusinessResultNotTransportError`（Governor）：**
断言预扣被拒时返回的是 `reserved=false` + 明确错误码，**而非** gRPC
传输错误，且**不**熔断。这三条一起才能锁住"瞬时争用 vs 真实耗尽"的
区分（这是我在 I3 修掉的缺陷的回归防线）。

## 5. 契约缺口的处理（本次自检的重点）

实现决策队列时发现 **`05 §6.2` 的 OrchestratorService 没有「读取任务图」
的 RPC** —— 它需要任务的角色、证据、失败记录才能渲染 06 §7.1 要求的
四要素卡片，而这些都不在 `NextReady.blocked_reasons` 里。

**按 `docs/09` R1**（「不得修改 05 契约，任何变更须走 `contract:` PR
且需双人 review」），自检时的正确处置是：

| 做法 | 是否采取 | 理由 |
|---|---|---|
| 自造一个 RPC 并改 proto | ❌ | 违反 R1；"边实现边改契约"等于取消"契约定死、实现可变" |
| 渲染空表格让人以为"当前没有决策项" | ❌ | 违反 `docs/10` §0（把"没查"伪装成"没问题"） |
| 填占位文本 / 编造置信度 | ❌ | 违反 P9（文档失真）；会让决策者基于错误前提判断 |
| 用契约内可得的信息 + 页面上显式声明缺口 | ✅ | 既前进又不越界 |

具体落地：用 `blocked_reasons`（`map<task_id, reason>`）呈现任务状态；
页面上用琥珀色区块声明缺口与正确的 `contract:` 流程；未知字段留空并
说明原因。**已登记为待办**：需 `contract:` PR 新增只读 `GetGraph`。
