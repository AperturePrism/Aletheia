# M1 · 光谱摄入（L0）

> 模块编号：M1 ｜ 层：L0 Spectrum Ingest ｜ 建议语言：**Go**
> 迭代：I1 ｜ 上游：无（基础模块） ｜ 下游：M2、M4

---

## 1. 职责

把工具执行的原始输出，**确定性地**转换为结构化证据光谱（EvidenceSpectrum）。

一句话：**M1 是系统唯一允许与外部工具交互的入口，也是"不让 LLM 碰命令行"这条规则的执行者。**

---

## 2. 边界

### 2.1 本模块做

| # | 职责 |
|---|---|
| R1 | 工具适配器注册与版本门禁 |
| R2 | 参数化 Schema 校验 → 确定性渲染 argv |
| R3 | 调用 ScopeService / GatewayService / SandboxService 完成执行前置检查 |
| R4 | 原始输出的 ANSI 清洗、确定性解析、类型化断言 |
| R5 | 无损折叠（保留行号可追溯性） |
| R6 | 实体草稿抽取（EntityDraft） |

### 2.2 本模块不做（越界即架构违规）

| # | 不做 | 归属 |
|---|---|---|
| N1 | **不判定漏洞**（不产出 Finding） | M4 |
| N2 | **不调用 LLM** | — （本模块零 LLM 调用） |
| N3 | **不做范围校验的决策**（只调用 ScopeService，不自行判断） | M6 ScopeKernel |
| N4 | 不做脱敏逻辑（只调用 GatewayService） | M6 PrivacyGateway |
| N5 | 不写心智地图（只产出 Spectrum，由 M2 消费） | M2 |
| N6 | 不生成 exec_id（只消费 Sandbox 签发的） | M6 Sandbox |

## 3. 依赖

| 依赖 | 用途 | 失败语义 |
|---|---|---|
| `SandboxService.Execute` | 在隔离环境执行工具，获取 exec_id | 失败 → `UPSTREAM_UNAVAILABLE`，任务标 FAILED |
| `ScopeService.Check` | 目标参数范围校验（工具层） | DENY → `SCOPE_VIOLATION` → **熔断整场会话** |
| `GatewayService.Tokenize` | 参数中的敏感值脱敏 | 失败 → 拒绝执行（不降级） |
| `GatewayService.ScanOutbound` | 输出出站泄漏校验 | 有命中 → `PRIVACY_LEAK_DETECTED`，阻断 |

## 4. 内部设计

### 4.1 适配器框架

每个工具一个适配器，实现统一接口：

```go
type Adapter interface {
    // 元信息
    Name() string
    SupportedVersions() VersionRange     // 版本门禁区间
    Schema() ParamSchema                 // 参数化 Schema

    // 确定性渲染
    RenderArgv(params map[string]string) ([]string, error)

    // 解析
    Parse(raw []byte, execID string) (*EvidenceSpectrum, error)

    // 折叠策略（各工具不同）
    FoldStrategy() FoldStrategy
}
```

### 4.2 参数化 Schema

```go
ParamSchema{
  "target": {Type: CIDR, Required: true, ScopeChecked: true},
  "ports":  {Type: PortRange, Default: "top1000"},
  "scripts":{Type: EnumList, Choices: nmapScriptAllowlist},
  "timing": {Type: Enum, Choices: []string{"T2","T3","T4"}},
}
```

**硬约束：**
- 不接受 `raw_command string` 类型参数（编译期就不给这个口子）
- `ScopeChecked: true` 的参数在渲染前必须经 ScopeService 校验
- 枚举类参数必须有白名单，禁止自由字符串

### 4.3 解析器规范（对 D9 缺陷的正面回应）

调研记录的三个真实翻车点，必须在解析器中显式处理：

| 翻车点 | 现实案例 | 处理方式 |
|---|---|---|
| 版本串混淆 | nmap 报 `2 (RPC #100000)`，被当成产品名传给 Metasploit | 前导数字守卫：`^\d+\s*\(` 命中则拒绝作为版本 |
| ANSI 污染 | `exploit/unix/\x1b[45mftp\x1b[0m/vsftpd_234` 被当作模块路径 | **进入解析前统一 `strip_ansi()`**，测试用例必须含转义序列 |
| Schema 参数名不匹配 | 模型传 `{"query":...}`，工具要 `{"keyword":...}`，被静默拒绝 | 参数校验**显式报错 `INVALID_ARGUMENT`**，禁止静默；同时提供常见别名映射表 |

**解析器实现要求：**
- 必须为**纯函数**（无 IO、无全局状态），便于测试与确定性验证
- 每个字段抽取必须配 `assert`（值域、长度、字符集）
- 无法解析的行进入 `ParseQuality.unparsed_lines` 并计入覆盖率分母，**不得静默丢弃**

### 4.4 无损折叠

```
原始 10,000 行
   │  模式提取（模板化）
   ▼
SpectrumLine[]  ← 每行带 orig_line_start / orig_line_end / fold_count
   │
   └─ 语义等价性要求：折叠前后，任何"哪些行包含 X"的查询结果必须一致
```

**折叠不丢语义的验证方法：** 对折叠前后各执行同一组查询（端口列表、服务版本、CVE 编号），结果集必须完全一致。此测试纳入 CI。

### 4.5 确定性保证

| 环节 | 保证手段 |
|---|---|
| argv 渲染 | 参数按 Schema 定义顺序拼接，map 迭代顺序不影响结果 |
| 解析 | 纯函数，无时间/随机/环境依赖 |
| 折叠 | 稳定排序（相同输入必得相同输出顺序） |
| 哈希 | `content_hash` 基于原始字节，非解析后结构 |

## 6. 测试要求

| 类别 | 要求 | 门禁 |
|---|---|---|
| 单元测试 | 解析器行覆盖率 **≥ 90%** | Q2 |
| 边界用例 | 必须覆盖：ANSI 转义、版本串前导数字、空输出、截断输出、超长单行（>1MB）、UTF-8 非法字节、CRLF/LF 混用、nmap 多目标并行输出交错 | Q2 |
| 确定性 | 相同输入运行 3 次，`content_hash` 与 `lines` 完全一致 | Q6 |
| 折叠语义 | 折叠前后查询结果集完全一致 | Q6 |
| 反注入 | 参数值中含 shell 元字符（`; | & $() \``）时，渲染结果不得产生注入 | Q3 |
| 泄漏 | 输出含真实 IP 时，ScanOutbound 必须阻断 | Q5 |
| 集成 | 端到端：nmap → Spectrum → 实体草稿数量符合预期 | Q1 |

**测试数据管理：** 所有原始输出样本存入 `tests/parsers/fixtures/`，标注来源工具版本；样本中禁止包含真实目标信息（用文档示例或自建靶场输出）。

## 7. 验收标准（DoD）

- [ ] 三个适配器（nmap / httpx / nuclei）在自建靶场上端到端跑通
- [ ] 解析器覆盖率 ≥ 90% 且边界用例全绿
- [ ] 相同输入 3 次运行产出字节级一致结果
- [ ] 折叠前后语义等价测试通过
- [ ] 参数化 Schema 消除命令行注入（含元字符的对抗测试通过）
- [ ] 版本不匹配时 fail-closed（返回 `TOOL_VERSION_MISMATCH`，不尝试解析）
- [ ] 零 LLM 调用（静态检查：模块内不得 import 任何模型 SDK）

---

## 8. 风险与降级

| 风险 | 缓解 |
|---|---|
| 工具版本升级导致解析失败 | 版本门禁拒绝不匹配版本；适配器声明支持区间；提供 `--tool-version-override` 仅限调试 |
| 新工具接入成本高 | 框架要求新增适配器只需实现接口 + 提供测试样本，单工具工作量控制在可控范围 |
| 折叠引入语义损失 | 语义等价测试作为 CI 门禁；提供 `fold=off` 调试开关 |
| 超长输出撑爆内存 | 流式解析 + 分块折叠；单行上限 1MB 超限则截断并记 warning |
