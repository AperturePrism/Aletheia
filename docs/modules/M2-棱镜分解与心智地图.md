# M2 · 棱镜分解与心智地图（L1）

> 模块编号：M2 ｜ 层：L1 Prism Decomposition ｜ 建议语言：**Go（核心）+ Python（查询 DSL）**
> 迭代：I4 ｜ 上游：M1 ｜ 下游：M3、M5、M7、M8

---

## 1. 职责

把 L0 产出的结构化光谱**分解为正交维度的实体**，并在**单一属性图**中维护跨会话持久的记忆。

一句话：**M2 是系统的唯一真源。上下文、agent 记忆、报告全部从它派生。**

---

## 2. 边界

### 2.1 本模块做

| # | 职责 |
|---|---|
| R1 | 光谱 → 实体/关系的分解（7 类实体） |
| R2 | 多源写入与冲突保留（不合并） |
| R3 | 时间版本管理（`valid_from` / `valid_to`）与历史回放 |
| R4 | 假设分支（创建 / 回滚 / 合并） |
| R5 | 子图投影（按焦点与半径） |
| R6 | 归档压缩（降采样为聚合节点，保留下钻能力） |

### 2.2 本模块不做

| # | 不做 | 归属 |
|---|---|---|
| N1 | 不决定"该查什么"（焦点由 M3 Autofocus 给出） | M3 |
| N2 | 不做 token 预算判断（只执行投影） | M3 |
| N3 | 不判定漏洞状态（Defect 的 Hypothesis→Confirmed 由 M4 驱动） | M4 |
| N4 | 不调用 LLM 做实体抽取（抽取在 M1 的解析器中完成） | M1 |
| N5 | **不采用多套存储**（不引入独立向量库/图库/摘要层） | — |

**关于 N5 的说明：** 调研发现 PentAGI 采用 PostgreSQL + pgvector + 可选 Neo4j + chain summarization 四套机制，其自身弱项即包含"组件多、心智负担高"。本项目坚持**单一图 + 逻辑视图投影**，向量检索仅作为可选辅助且必须过相关性阈值（对 D8 RAG 负收益的回应）。

## 4. 内部设计

### 4.1 存储模型

```
PostgreSQL（主库）
├── entity          (entity_id, kind, attrs jsonb, valid_from, valid_to, version,
│                    confidence, is_hypothesis, branch_id)
├── relation        (relation_id, from_entity, to_entity, type, attrs, confidence,
│                    valid_from, valid_to)
├── provenance      (entity_id, source_kind, evidence_id, exec_id, observed_at)
├── branch          (branch_id, parent_branch, created_at, status)
└── archive_node    (aggregate 实体，带 downlink 指向归档前的实体集)

向量检索（可选，pgvector 同库）
└── embedding       (entity_id, vector)  ← 检索结果必须过相关性阈值才注入

原始输出
└── 内容寻址文件系统（M1 写入，M2 只存引用）
```

**单库原则：** 图、向量、关系数据同库，避免跨存储同步。规模超限时按会话分区，而非拆库。

### 4.2 七视图投影

不建立物化副本，用**视图 + 索引**实现：

| 视图 | 投影方式 | 典型查询 |
|---|---|---|
| Asset | `kind=ASSET` | 网段内所有主机 |
| Service | `kind=SERVICE` + `RUNS_ON` | 某主机的开放端口 |
| Identity | `kind=IDENTITY` + `AUTHENTICATES_TO` | 某服务可用凭据 |
| Endpoint | `kind=ENDPOINT` + `BELONGS_TO` | 某服务暴露的 URL |
| Defect | `kind=DEFECT` + 状态过滤 | 某服务的未确认缺陷 |
| Path | `kind=PATH` + `hops` 有序遍历 | 从边界到目标的路径 |
| Timeline | `kind=TIMELINE` 按时间排序 | 某时间段内发生的动作 |

### 4.3 多源写入与冲突保留（对 D12 级联失败的回应）

```
三个来源对同一 SERVICE 写入不同版本号
         │
         ▼
  ┌──────────────────────────────┐
  │ 不覆盖、不合并：              │
  │ · 各写入一条 provenance       │
  │ · 若属性值冲突 → 新增版本     │
  │ · 生成 Conflict 记录          │
  │   → conflict_type:            │
  │     VALUE_MISMATCH            │
  └──────────────────────────────┘
         │
         ▼
  投影时按 confidence 与时间排序，全部呈现
```

**设计意图：** 侦察漏掉一个服务不再导致下游永不测试它——多源冗余天然消解级联失败。

### 4.4 时间版本与回放

```sql
-- 写入：旧版本置 valid_to，新增版本
UPDATE entity SET valid_to = $now WHERE entity_id = $id AND valid_to IS NULL;
INSERT INTO entity (...) VALUES (..., valid_from := $now, valid_to := NULL, version := $n);

-- 回放到时刻 T
SELECT * FROM entity
WHERE valid_from <= T AND (valid_to IS NULL OR valid_to > T);
```

**回放契约：** `SnapshotAt(T)` 必须返回与"当时实际认知状态"字节级一致的结果。测试方式：连续写入 N 次，回放到每个中间时刻，与当时的实时快照对比。

### 4.5 假设分支

```
main 分支
   │
   ├── branch_A（假设：存在 SSRF）
   │      └─ 写入的实体全部带 is_hypothesis=true, branch_id=branch_A
   │
   └── 验证失败 → RollbackBranch(branch_A)
          └─ 该分支写入的实体全部标记 valid_to（软删除）
             → 图状态与分支前一致
```

**回滚契约：** `RollbackBranch` 后，`SnapshotAt(分支前的时刻)` 的结果必须与**从未创建该分支**时完全一致（字节级对比测试）。

`MergeBranch`：仅当分支内的实体通过 M4 的闸门（非 Hypothesis）才允许合并，避免假设污染主分支。

### 4.6 归档（对"有损摘要"的替代方案）

```
活跃实体（< 7 天）  → 完整保留
           │ 降采样
           ▼
归档节点（聚合）    → 保留：计数、时间范围、属性值域、downlink 指针
                     丢失：单条明细（但可经 downlink 恢复）
```

**与 chain summarization 的区别：** 摘要是**有损且不可逆**的；归档是**可下钻的**——需要明细时沿 downlink 取回，不依赖 LLM 重新生成。

## 6. 测试要求

| 类别 | 要求 | 门禁 |
|---|---|---|
| 多源一致性 | 三源写入同一实体，全部 provenance 可追溯，Conflict 正确生成 | Q1 |
| 回放保真 | 回放到任意历史时刻，与当时实时快照字节级一致 | Q1 |
| 分支隔离 | 分支内写入不影响主分支投影结果 | Q1 |
| 回滚一致性 | 回滚后图状态与"从未创建分支"完全一致 | Q1 |
| 幂等性 | 相同 `spectrum_id` 重复 Ingest 无副作用 | Q1 |
| 凭据安全 | 实体属性中 `credential_ref` 为脱敏 token，无明文（正则扫描） | Q5 |
| 归档可下钻 | 归档后沿 downlink 恢复明细，结果与归档前一致 | Q1 |
| 性能 | 10 万实体规模下，单次投影 P95 < 200ms | — |

## 8. 风险与降级

| 风险 | 缓解 |
|---|---|
| 图规模导致查询变慢 | 按会话分区；热点视图物化（可重建，非真源）；定期归档 |
| 冲突过多导致投影噪声 | Conflict 是**信号**而非噪声：M3 投影时优先呈现，冲突本身驱动深挖任务 |
| 分支过多导致状态爆炸 | 限制并发分支数（默认 8）；超限拒绝创建而非静默降级 |
| 回放依赖严格的时间语义 | 所有写入走统一时间源；禁止应用层自行生成时间戳 |
