# M6 · 横切能力层

> 模块编号：M6 ｜ 层：横切（Cross-cutting） ｜ 建议语言：**Go**
> 迭代：I0（骨架） + I3（安全能力） + I12（加固） ｜ 上游：无 ｜ 下游：全部模块

---

## 1. 职责

提供全部模块共用的**基础设施与约束能力**。M6 的定位不是"功能"，而是**边界**：

> **M6 是系统里唯一有权说"不许"的模块。**

包含七个子模块：

| 子模块 | 一句话职责 |
|---|---|
| **ScopeKernel** | 越界即熔断 |
| **PrivacyGateway** | 真实值不出域 |
| **AuthorizationAnchor** | 无授权不启动 |
| **CostGovernor** | 预算是一等约束 |
| **Sandbox** | 一切执行在隔离环境，exec_id 唯一签发者 |
| **Observability** | 决策可溯源 |
| **Checkpoint** | 支持回放与分支的存储基础设施 |

---

## 2. 边界

**M6 不得反向依赖任何业务层模块（L0–L4）。** 这是架构分层硬约束——横切层被所有层依赖，若它依赖业务层将形成循环。

---

## 3. ScopeKernel（范围内核）

### 3.1 三重校验

```
出站请求（目标地址）
   │
   ├─ L1 network layer
   │    目标 IP/CIDR 是否在 scope 白名单内？
   │    失败 → DENY(failed_layer=NETWORK)
   │
   ├─ L2 tool_param layer
   │    工具参数中的 target 字段是否通过 scope 校验？
   │    （由 M1 在渲染 argv 前调用）
   │    失败 → DENY(failed_layer=TOOL_PARAM)
   │
   └─ L3 post_dns layer
        DNS 解析后的真实 IP 再复核一次
       （防 DNS rebinding / HTTP 重定向 / IPv6 编码绕过）
       失败 → DENY(failed_layer=POST_DNS)
```

### 3.2 熔断语义（不可协商）

**`SCOPE_VIOLATION` → 立即终止整场会话，不是跳过该请求、不是告警后继续。**

依据（调研 D11）：三大失败模式之一是"范围控制弱 → agent 触碰从未纳入演练的系统/账号/工具"。工具层必须限制目标、动作与工具使用，**而不只是限制最终报告**。

### 3.3 必须防御的绕过手法（测试用例必备）

| 绕过手法 | 防御 |
|---|---|
| DNS rebinding | L3 复核（解析后再次校验 IP） |
| HTTP 301/302 重定向到范围外 | 重定向目标重新走 L1 校验 |
| 十进制/八进制/十六进制 IP 编码 | 统一规范化为点分十进制后再比对 |
| IPv6 映射 IPv4（`::ffff:1.2.3.4`） | 展开并规范化 |
| 通配符 DNS 指向范围外 | L3 复核 |
| URL 用户信息段（`http://allowed@evil.com`） | 解析出真实 host 而非 userinfo |
| 超长域名截断 | 长度上限 + 完整解析校验 |

**每个手法必须有对应测试用例，越界测试 100% fail-closed（CI 红线 Q4）。**

### 3.4 速率限制

按目标 + 会话维度限流，防止被当作规模化攻击工具（对 D16 的回应）。

## 4. PrivacyGateway（隐私网关）

### 4.1 双向映射

```
真实值                          模型可见值
10.40.23.191        ──────▶    IP_PRIVATE_001
db.internal.corp    ──────▶    HOST_INTERNAL_001
admin:P@ssw0rd      ──────▶    CRED_001
/opt/app/config.yml ──────▶    PATH_INTERNAL_001
                                   │
       ◀──── 工具执行前一刻本地回注 ───┘
```

**确定性要求：** 同一真实值在同一会话内必须映射到同一 token（不是随机），否则模型无法建立关联。

**映射表安全：**
- 仅存本地，加密存储（密钥由启动时派生，不落盘）
- **不落普通日志**（日志中只有 token）
- 映射表本身不出现在任何出站流量中

### 4.2 出站二次扫描

```python
LEAK_PATTERNS = {
    "IP_PRIVATE": r"\b(10\.|172\.(1[6-9]|2\d|3[01])\.|192\.168\.)\d+\.\d+\b",
    "HOST_INTERNAL": r"\b[\w.-]+\.(internal|corp|local|lan)\b",
    "EMAIL": r"\b[\w.+-]+@[\w.-]+\.\w+\b",
    "CREDENTIAL": r"(?i)(password|passwd|pwd|secret|token|api[_-]?key)\s*[:=]\s*\S+",
    "PATH_INTERNAL": r"(?<![\w/])/(opt|srv|home|etc)/[\w./-]+",
}
```

命中 → `PRIVACY_LEAK_DETECTED` → **阻断该次出站，不降级**。

**默认强制：** PrivacyGateway 默认开启且**无 UI 开关**；只能通过配置文件显式禁用，且禁用时启动日志高亮告警并写入审计。

### 4.3 验证方法（对齐 Darkmoon 的验证方式）

在 OWASP Juice Shop 类靶场上**全程开启网关**运行，抓包验证：**模型侧流量中零真实 IP / 域名 / 凭据**。这是 CI 红线 Q5。

## 5. AuthorizationAnchor（授权锚定）

对 D16（被武器化滥用）的回应。

```
启动
  │
  ├─ 是否提供授权凭证？
  │    · 授权书文件（含哈希）
  │    · 或工单号
  │    · 或 ROE 文件
  │
  ├─ 否 → 进程以非零码退出（拒绝启动，不是警告）
  │
  └─ 是 → 凭证与 scope 绑定，写入不可篡改审计日志

审计日志：append-only + 哈希链
```

**设计立场：** 这是**硬门禁**而非提示。开源渗透工具同时降低专业红队门槛和滥用门槛（HexStrike 已被报道用于自动化利用某 Citrix 漏洞），项目方有责任设置最低门槛。

## 6. CostGovernor（成本治理）

### 6.1 预算作为一等约束

| 层级 | 约束 |
|---|---|
| 会话总预算 | 硬上限；80% 触发光圈收窄；100% 熔断 |
| 任务预算 | 单任务上限；超限强制收窄光圈重试 |
| Agent 预算 | 按角色分配（Exploiter 多、Reporter 少） |
| 工具调用次数 | 按 agent 类型设上限（防死循环） |
| 模型档位 | 分级路由 |

### 6.2 预扣 + 结算

```
Reserve(task_id, estimated_tokens)  →  预扣，失败则拒绝执行
Consume(task_id, actual_tokens)     →  实际结算
State()                              →  当前状态（含 circuit_open 标志）
```

**预扣制的原因：** 防止并发任务同时消耗导致超支。预扣失败即拒绝，符合 fail-closed 原则。

## 7. Sandbox（沙箱）

### 7.1 隔离要求

| 项 | 要求 |
|---|---|
| 运行时 | Docker（默认）/ Kata Containers（高安全场景） |
| 镜像 | 只读基础镜像 + 临时工作卷 |
| 网络 | 出站必须经 ScopeKernel 代理 |
| 工具 | **白名单**（不是黑名单） |
| 凭据 | 宿主凭据不入容器；容器内凭据由 Sandbox 临时注入 |
| 权限 | 最小权限，禁止 `--privileged` |

### 7.2 exec_id 签发（关键安全边界）

```go
// Sandbox 是 exec_id 的唯一合法签发者
type SignedExecId struct {
    ExecID    string    // exec_{uuid7}
    Signature []byte    // Sandbox 私钥签名
    IssuedAt  time.Time
}
```

**为什么必须签名：** M4 的 G-1 闸门依赖 exec_id 判断"是否真的执行过"。若 agent 能自行生成 exec_id，G-1 即刻失效，D2（自言自语）防御形同虚设。**私钥仅在 Sandbox 进程内，不出容器运行时。**

## 8. Observability

### 8.1 全链路追踪

OpenTelemetry，每个 span 关联：
`session_id` / `task_id` / `agent_id` / `exec_id` / 地图实体 ID / `evidence_id`

### 8.2 决策溯源（对 D14 的回应）

必须能回答三个问题：

| 问题 | 追溯路径 |
|---|---|
| agent 为什么这么做？ | span → 决策依据的地图实体 ID → `selection_reasons` |
| 这个结论的证据是什么？ | finding_id → assertions → evidence_ids → exec_id → 原始输出行号 |
| 这行数据从哪来？ | 原始输出文件 + 行号 → SpectrumLine → EntityDraft → Entity |

### 8.3 零遥测默认（对 D18 的回应）

**默认不发送任何遥测。** 如需开启必须显式 opt-in，且发出内容经 PrivacyGateway 脱敏。对齐 CAI 的做法——"发送遥测但透明地说明"，本项目更严格：默认不发。

## 13. 风险与降级

| 风险 | 缓解 |
|---|---|
| DNS 复核引入延迟 | 结果缓存（短 TTL）；复核失败即拒绝（fail-closed） |
| 隐私网关影响工具功能 | token 回注在工具执行前一刻完成，工具看到真实值；仅模型侧脱敏 |
| 容器逃逸 | 最小权限 + 只读镜像 + 无宿主凭据；定期对抗测试 |
| 预算估算不准 | 保守系数；预扣高于估算；结算后回冲 |
| 授权锚定被绕过 | 凭证校验在进程启动最早期；校验失败直接退出（不留可绕过窗口） |
