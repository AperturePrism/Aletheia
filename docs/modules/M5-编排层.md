# M5 · 编排层（L4）

> 模块编号：M5 ｜ 层：L4 Orchestration ｜ 建议语言：**Python**
> 迭代：I6（规划与调度） + I9（后渗透扩展） ｜ 上游：M3、M4、M6 ｜ 下游：M7、M9

---

## 1. 职责

把「用户目标 + 授权范围 + 预算」转化为**可求解的任务图**，调度 agent 执行，并在失败时改写策略。

一句话：**M5 决定"做什么、什么顺序、谁来做"，但不决定"上下文里放什么"（M3）也不决定"结论是否成立"（M4）。**

---

## 2. 核心设计决策：不让 LLM 做长程规划

**依据：** CHECKMATE 的做法 —— 让 LLM 生成 PDDL 领域描述，交给经典规划器求解，比 Claude Code 原生 agent **成功率高 20%+、快 50%+、便宜 50%+**。

**教训：LLM 不擅长的长程规划，交给算法。**

```
┌────────────────────────────────────────────────────┐
│ LLM（Planner）                                      │
│ 只回答一个窄问题：                                   │
│   "针对这个目标，有哪些任务？它们之间的依赖是什么？"    │
│ 输出：TaskGraph（纯结构，不含执行序列）               │
└───────────────────────┬────────────────────────────┘
                        ▼
┌────────────────────────────────────────────────────┐
│ 确定性规划器（零 LLM）                               │
│  · 拓扑排序                                        │
│  · 资源约束求解（预算分配、并发上限）                 │
│  · 关键路径识别                                    │
│  · 输出：可执行序列 + 并发分组                       │
└───────────────────────┬────────────────────────────┘
                        ▼
                   Scheduler 分发
```

**契约约束：** `OrchestratorService.NextReady` 的实现**禁止调用 LLM**（CI 静态检查）。

## 4. 内部设计

### 4.1 Agent 池

| Agent | 职责 | 建议模型档位 | 启用条件 |
|---|---|---|---|
| **Recon** | 资产/服务发现，写入地图 | 小模型 | 必经 |
| **Scanner** | 已知漏洞匹配、配置检查 | 小模型 | 高确定性任务 |
| **Fuzzer** | 参数/路径模糊测试 | 小模型 | 需大量重复动作 |
| **Exploiter** | 利用链构建与执行 | **大模型** | 高价值、高不确定性 |
| **PostExploit** | 内网横向、凭据收集、提权 | 大模型 | 获得立足点后 |
| **Reporter** | 从地图与账本生成报告（纯整理） | 小模型 / 确定性 | 会话结束 |
| **Refiner** | 观察失败模式，改写其他 agent 指令 | 大模型 | 有失败记录时 |
| **Arbiter** | 终止/结论独立校验（实现在 M4） | 中模型 | 终止请求时 |

**按需实例化原则（对 PentestEval 结论的回应）：** "标准 ReAct 循环常已足够，甚至优于复杂的多 agent 架构"。因此：

- **不默认启动全部 agent**
- 多 agent 只在**高价值环节**启用（利用链、后渗透）
- 单步高确定性任务用单 agent + ReAct 循环

### 4.2 Refiner（采纳 D-CIPHER 的 auto-prompter）

```
失败记录 FailureRecord[]
        │
        ▼
┌──────────────────────────────────────┐
│ 失败模式库（结构化，非纯文本）：        │
│   CONTEXT_MISSING    上下文缺关键实体  │
│   TOOL_MISUSE        参数/工具选错     │
│   WRONG_HYPOTHESIS   假设方向错误      │
│   TIMEOUT            超时             │
│   PREMATURE_STOP     过早放弃          │
│   HALLUCINATION      幻觉             │
└──────────────────┬───────────────────┘
                   ▼
        Refiner 生成改写后的指令
                   │
                   ▼
        plan_revision += 1，重试任务
```

**与简单重试的区别：** 简单重试会重复同样的失败；Refiner 依据**结构化的失败类型**改写指令（如 `CONTEXT_MISSING` → 提高光圈档位重新装配上下文）。

### 4.3 检查点与分支

```
每个任务提交前创建检查点：
  · 心智地图版本号（M2 支持 SnapshotAt）
  · 证据账本水位（append-only，按 ID 截断）
  · 预算状态快照（M6 Governor）
  · TaskGraph 版本（plan_revision）

rewind(checkpoint_id)
  · 恢复地图到该点
  · 账本保留（append-only 不可回滚，但标记水位以界定"本分支新证据"）
  · 失败记录保留 → 供 Refiner 学习

fork(checkpoint_id) → branch_id
  · 创建平行分支探索备选路径
  · 共享已 CONFIRMED 的证据
  · 隔离探索性假设（is_hypothesis=true）
```

**注意：账本不回滚。** 证据是历史事实，"探索过但失败"本身是有价值的信息。分支隔离靠 `branch_id` 标记而非删除。

### 4.4 熔断器

| 条件 | 阈值（默认） | 动作 |
|---|---|---|
| 单 agent 幻觉计数 | > 3 | 停止该 agent → Refiner 改写 |
| 会话幻觉占比 | > 10% | 终止会话，报告标记"证据不可信" |
| 预算消耗 | ≥ 80% | 光圈自动收窄（M3），只保留高价值任务 |
| 预算耗尽 | 100% | **硬熔断**，产出中间报告 |
| 单任务 token | 超任务预算 | 强制收窄光圈重试 1 次，失败则 SKIPPED |
| **Scope 越界尝试** | 任何一次 | **立即 fail-closed 熔断全部**，记录审计事件 |
| 无进展步数 | > 15 | rewind 至最近检查点 |
| 总运行时长 | 可配置上限 | 硬熔断 |

**熔断的不可协商性（原则 P-4）：** 全部 fail-closed，禁止"告警后继续"。

## 6. 测试要求

| 类别 | 要求 | 门禁 |
|---|---|---|
| 规划器确定性 | `NextReady` 相同输入产出相同序列；静态检查确认无 LLM 调用 | Q1 |

| 熔断全覆盖 | 8 类熔断条件每类都有触发测试；越界熔断 100% fail-closed | **Q4（红线）** |

| 分支隔离 | fork 分支的假设不污染主分支 | Q1 |

## 8. 风险与降级

| 风险 | 缓解 |
|---|---|
| Planner 输出的任务图质量差 | 结构化输出校验 + 人工可编辑；保留 plan_rationale 供审计；提供任务图模板库 |
| Agent 池通信开销过大 | 只在高价值环节启用多 agent；其余用单 agent ReAct |
| 熔断过敏感导致任务过早终止 | 阈值外置可调；无进展检测用滑动窗口而非单点判断 |
| 后渗透能力仍弱于人类红队 | **在文档中明确声明此边界**，不宣称超越专业红队 |
| 检查点存储膨胀 | 仅保留最近 N 个检查点（默认 20）+ 每个里程碑保留一个 |

## 9. 已知能力边界（必须写入对外文档）

对照 ARTEMIS 研究结论（人类唯一决定性优势在"创造性利用链、业务逻辑、GUI 流程、无人记录过的新攻击面"）：

- **本项目的后渗透能力设计目标是对齐并优于同类开源项目，但明确弱于专业人类红队**
- 多 agent 协作提升的是**覆盖面与一致性**，不是**创造性**
- 人类应在高价值决策点（利用链方向、业务逻辑判断）保持介入 —— 这不是缺陷，是设计（依据：全自主 21% vs 有人类提示 64%）
