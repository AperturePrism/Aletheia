# M8 · 业务逻辑意图建模（Intent Modeling）

> 模块编号：M8 ｜ 层：跨层（L1 写入 + L5 判定） ｜ 建议语言：**Python**
> 迭代：I10 ｜ 上游：M2、M7 ｜ 下游：M9

---

## 1. 职责

从可获取的契约输入中抽取**"应用应该做什么"**的行为契约，然后通过**契约违背检测**发现业务逻辑漏洞。

一句话：**不检测"什么模式危险"，而检测"实际行为与预期行为的偏离"。**

---

## 2. 行业空白（立项依据 G2）

**ARTEMIS 研究（2025-12）在 8,000 台主机的真实企业网络中得出的结论：**

> AI 排名第 2，成功率 82%，击败 10 名人类渗透测试员中的 9 名，成本 $18/小时（人类 $60+）。
> 但**关键 Web 漏洞中约 70% 属于业务逻辑缺陷，当前没有任何自主 agent 能可靠检测**。

**这是全行业唯一的、被明确点名的 0% 区域。** Aletheia 的第三个"第一"就是给出这部分的**首个可复现检出数字**。

为什么所有 agent 都失明：现有 agent 做的是**模式匹配**（"这个参数看起来像 SQL 注入点吗？"）。业务逻辑漏洞没有"危险模式"——`POST /transfer {from: A, to: B, amount: 100}` 本身完全合法，问题在于**A 是否有权从别人账户转账**。这需要理解**授权语义**，而非匹配语法模式。

## 3. 边界

### 3.1 本模块做

| # | 职责 |
|---|---|
| R1 | 契约抽取：OpenAPI / 抓包流量 / 源码 / 文档 → Endpoint Contract |
| R2 | 状态机推断（合法转移序列） |
| R3 | 权限矩阵构建（主体 × 资源 × 动作） |
| R4 | 契约违背检测（六类） |
| R5 | 自建业务逻辑靶场 |
| R6 | 可复现检出数字产出 |

### 3.2 本模块不做

| # | 不做 | 归属 |
|---|---|---|
| N1 | 不做通用漏洞扫描 | M1 / M7 |
| N2 | 不判定漏洞成立（提交 M4 走闸门） | M4 |
| N3 | 不声称对黑盒无文档目标有通用能力 | — |
| N4 | 不做通用 WAF 绕过 | — |

**N3 是诚实性要求：** 契约抽取依赖可获取的输入。对完全黑盒且无任何文档的目标，本模块只能做基于流量的**启发式推断**，覆盖率显著下降。**这一限制必须写入文档与报告，不做过度承诺。**

## 4. 内部设计

### 4.1 契约抽取

```
输入源                        抽取                    契约模型
──────────────────────────────────────────────────────────────
OpenAPI / Swagger    ──┐
抓包流量（HTTP history）──┤   端点语义抽取   ┌──────────────────────────┐
源码（路由/中间件/注解）──┼──▶              │  Endpoint Contract        │
文档 / 需求 / 工单    ──┘                   │  · 认证要求               │
                                            │  · 授权主体范围            │
                                            │  · 参数语义与合法边界       │
                                            │  · 状态机（合法转移）       │
                                            │  · 数据可见性规则          │
                                            │  · 数量/频率约束           │
                                            └──────────┬───────────────┘
                                                       │
                            实际探测（黑盒）───────────┤
                                                       ▼
                                          ┌────────────────────────┐
                                          │  契约违背检测（六类）    │
                                          └────────────────────────┘
```

**抽取优先级：** OpenAPI（最可靠）> 源码注解 > 抓包流量推断 > 文档（最不可靠）。每个契约字段带 `source` 与 `confidence`，低置信度字段参与检测时降权。

### 4.2 六类契约违背

| # | 类型 | 契约违背形式 | 检测方式 | 常见实例 |
|---|---|---|---|---|
| **BL1** | **越权访问（IDOR 升级版）** | 主体应仅访问自身资源 | **会话隔离探测**：显式绑定 `session_id`，用 A 会话访问 B 的资源 | 改 `user_id` 参数读他人订单 |
| **BL2** | **价格/数量篡改** | 金额应由服务端计算 | 篡改后比对服务端响应与预期 | 改 `price=0.01` |
| **BL3** | **流程绕过** | 状态机不应允许 X→Z（跳过 Y） | 按推断的状态机枚举**非法转移** | 跳过支付直接确认订单 |
| **BL4** | **配额绕过** | 计数应单调递增不可重置 | 并发 / 重放探测 | 重置免费试用次数 |
| **BL5** | **权限提升链** | 低权限不应获得高权限操作 | 权限矩阵交叉验证 | 普通用户调用管理员接口 |
| **BL6** | **竞态（TOCTOU）** | 并发下一致性应保持 | 并发请求 + 状态比对 | 并发提现超额 |

**BL1 直击 D7（多会话状态混淆）：** 调研实测中，agent 经常混淆 A/B 账号的 cookie，从错误上下文执行动作，最终判定"漏洞不存在"（**假阴性**）。M8 用显式 `session_id` 绑定解决此问题——会话是独立的一等对象（见契约 §3 IDENTITY 实体）。

### 4.3 会话隔离探测（BL1 核心机制）

```
准备：注册/获取两个独立身份  ──▶  Session A（低权限）、Session B（低权限）
      （M8 自行完成注册流程，不依赖人工）

探测：对每个"资源级"端点，构造交叉访问矩阵：

        访问者\资源      A 的资源    B 的资源
        ─────────────────────────────────────
        Session A         ✅ 期望     ❌ 期望拒绝
        Session B         ❌ 期望拒绝  ✅ 期望

      实际结果与期望不一致 ──▶ 契约违背（越权）

强证据要求：必须实际取回 B 的资源内容（DATA_RETURNED 副作用观测），
           仅返回 200 状态码不足以判定（可能是空壳响应）
```

**最后一条是 M4 的 G-3 在业务逻辑场景的应用** —— 避免"只看状态码就判定成功"这类 D1 幻觉式成功。

### 4.4 状态机推断与非法转移枚举

```
从抓包流量提取端点调用序列
        │
        ▼
构建转移图：节点 = 端点（含方法），边 = 观测到的调用顺序
        │
        ▼
推断合法状态机（含终端状态判定）
        │
        ▼
枚举"未观测到但在语义上可能"的转移
        │
        ▼
探测非法转移：跳过中间步骤直接请求终端端点
   （如：直接 POST /order/confirm 而不经过 /order/pay）
```

### 4.5 自建业务逻辑靶场

行业空白意味着**没有现成靶场可测**。必须自建。

靶场设计要求（`labs/bizlogic/`）：

| 要求 | 说明 |
|---|---|
| 缺陷数量 | ≥ 10 类业务逻辑缺陷，覆盖 BL1–BL6 每类至少 1 个 |
| 真实度 | 使用真实业务语义（电商/银行/审批流），非人工玩具 |
| 可复现 | Docker Compose 一键起，状态可重置 |
| 有/无契约双模式 | 同一靶场提供"有 OpenAPI"与"无 OpenAPI"两种部署，用于分别统计覆盖率 |
| 已知真值 | 缺陷清单与位置作为 ground truth，用于计算检出率与误报率 |
| 防污染 | 靶场代码不公开在训练语料中（自建，非公开项目） |

**双模式是诚实性的关键** —— 只报"有契约"的数字会高估能力。

## 6. 测试要求

| 类别 | 要求 |
|---|---|
| 契约抽取 | OpenAPI 抽取字段完整率 ≥ 95%；流量推断的端点覆盖率 ≥ 80% |
| 六类覆盖 | BL1–BL6 每类至少 1 个靶场用例被检出 |
| 强证据 | 越权判定必须基于 `DATA_RETURNED` 副作用，禁止仅凭状态码 |
| 会话隔离 | 双身份 cookie 不混淆（构造 100 组交叉访问，错误绑定率为 0） |
| 假阴性 | 对靶场已知缺陷的漏报率单独统计并公开 |
| 双模式 | "有契约"与"无契约"两种部署分别给出数字 |
| 可复现 | 第三方在干净环境重跑得到同量级结果 |

## 8. 风险与降级

| 风险 | 缓解 |
|---|---|
| 黑盒无文档目标覆盖率低（**最可能的现实**） | 分场景统计；以流量启发式兜底；**明确标注不宣称为通用能力**；报告覆盖率而非单一数字 |
| 自建靶场代表性受质疑 | 使用真实业务语义；公开靶场与 ground truth 供第三方验证；同时跑公开靶场（如有）对比 |
| 会话隔离探测需要注册能力 | 提供注册流程自动化；若目标不允许注册则明确报告该场景不支持 |
| 竞态检测需要并发控制 | 精确控制并发时序；多次重试确认（竞态有概率性，需统计显著性） |
| 状态机推断错误导致误报 | 推断来源带 confidence；低置信度转移只标记不判定 |

---

## 9. 立场的诚实声明（必须写入对外文档）

> ARTEMIS 的研究指出，人类在业务逻辑上的优势是**决定性的**。M8 的目标不是取代这种判断，而是把其中**可形式化的部分**（授权语义、状态机、权限矩阵）自动化。
>
> **我们明确承认：** 业务逻辑漏洞中仍有相当一部分依赖对业务意图的深层理解（如"这个折扣策略是否应该被叠加"），形式化契约无法覆盖。M8 给出的是**可复现的下界**，不是能力的上界。
