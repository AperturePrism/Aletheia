# M9 · 评测 Harness

> 模块编号：M9 ｜ 层：跨层（支撑） ｜ 建议语言：**Python**
> 迭代：I11 ｜ 上游：M4、M5 ｜ 下游：无

---

## 1. 职责

提供**可被第三方复现**的评测能力：基准适配、靶场编排、指标计算、结果报告。

一句话：**M9 是项目诚实性的技术保障 —— 所有对外数字必须由它产生。**

---

## 2. 边界

### 2.1 本模块做

| # | 职责 |
|---|---|
| R1 | 公开基准适配器（CyBench / CVE-Bench / XBOW validation / HTB Range） |
| R2 | 自建靶场编排（Juice Shop / 业务逻辑靶 / 内网多跳靶） |
| R3 | 标准指标计算 |
| R4 | **新增指标**计算（本项目定义的行业空白指标） |
| R5 | 结果报告生成（含失败案例分析） |
| R6 | 可复现性保障（环境冻结、随机种子固定） |

### 2.2 本模块不做

| # | 不做 |
|---|---|
| N1 | 不修改被测系统的行为（评测必须对被测系统透明） |
| N2 | **不允许手工填数**（所有指标必须由脚本计算） |
| N3 | 不选择性报告（失败案例必须一并输出） |

## 3. 评测基线（必须引用，否则无法证明改进）

| 指标 | 行业基线 | 来源与条件 |
|---|---|---|
| one-day CVE 利用率（给定通告描述） | 87% | Fang et al. 2024 · GPT-4 · **有描述**【A】 |
| one-day CVE 利用率（无描述） | 7% | 同上 · **唯一变量是去掉描述**【A】 |
| 真实条件 CVE 利用 | 13% | CVE-Bench（ICML 2025 Spotlight）· 40 个严重漏洞【A】 |
| 白盒 Web/API | 96.15%（100/104） | Shannon · **XBOW 清洗变体**（与黑盒不可比）【B】 |
| 黑盒 Web | ~85% | XBOW 自报【C】 |
| 子任务完成率（领域微调） | 79.17% | xOffense（Qwen3-32B 微调）【A】 |
| 0day 利用（多 agent 团队） | 42% pass@5 | HPTSA【A】 |
| HTB 靶机（多 agent） | 44.0% | D-CIPHER【A】 |
| CyBench（多 scaffold Blackboard） | 57.6%（19/33） | CSI【B】 |
| 端到端流水线（全自主） | 31% | PentestEval【A】 |
| 端到端（有 vs 无人类提示） | 64% vs 21% | AutoPenBench【A】 |
| HTB 困难靶机 | ≈0% | HTB AI Range · 所有被测模型【A】 |
| 链式漏洞成功率 | ~16% | "Hackers or Hallucinators?"【A】 |
| 合成漏洞检出（AIxCC 决赛） | 86% | DARPA【A】 |
| 补丁成功率（AIxCC 决赛） | 68%，平均 45 分钟 | DARPA【A】 |
| 单次利用成本（最优） | $0.56 / solve | GCAI【B】 |
| 单任务算力成本（AIxCC） | ~$152 | DARPA【A】 |
| 实网渗透成本 | $18/小时 | ARTEMIS【A】 |

**引用纪律（四项缺一不可）：** 来源（arXiv 号/仓库/独立评测）+ 条件（是否给定描述、白盒还是黑盒、是否有人类提示）+ 时点 + 置信度（A 同行评审 / B 单一权威 / C 二手转述）。

> **反面案例：** "AI 渗透成功率达 87%" —— 缺失全部四项，实际含义是"给定通告描述的理想条件下 GPT-4 对 one-day 漏洞的利用率"，去掉描述即降至 7%，真实条件下为 13%。

## 4. 本项目定义的新指标

行业空白 G1（可证明性）没有现成指标，必须自定义。

| 指标 | 定义 | 目标 | 对应缺陷 |
|---|---|---|---|
| **幻觉率** | 被 agent 声称但无法在证据账本中找到支撑的结论占比 | **0** | D1 / D2 / D3 |
| **证据可复现率** | CONFIRMED 状态中能在干净环境重放成功的比例 | **100%** | D1 |
| **越界尝试率** | ScopeKernel 拦截的越界请求数 | **0**（非 0 即缺陷） | D11 |
| **实体召回率** | 跨任务场景下相关实体被正确投影进上下文的比率 | **≥95%** | D4 |
| **每元漏洞成本** | 总成本 / CONFIRMED 漏洞数 | 持续下降 | G5 |
| **假阴性率** | 已知 ground truth 缺陷中未被检出的比例 | 单独公开 | D7 |
| **证据归因准确率** | 证据↔断言关联正确的比例 | **100%** | D1 |

**这些指标本身是项目的可交付物之一。** 即使检出率不理想，只要能给出这些行业此前无法量化的数字，就已经推进了领域。

## 5. 内部设计

### 5.1 基准适配器

```python
class BenchmarkAdapter(Protocol):
    def setup(self) -> Environment:          # 起靶场，返回环境句柄
    def tasks(self) -> list[BenchmarkTask]:  # 返回任务清单（含 ground truth）
    def run_task(self, task, system) -> TaskResult:
    def teardown(self) -> None:
    def reset(self) -> None:                 # 状态重置（可重复评测）
```

**适配器清单：**

| 基准 | 类型 | 适配要点 |
|---|---|---|
| CyBench | CTF（40 题） | 需 CTFd 集成，自动下载附件与启动实例 |
| CVE-Bench | 真实 Web 漏洞（40 个） | 需容器编排；**用于对标 13% 基线** |
| XBOW validation | 真实漏洞集 | **选它是因为污染风险低**（对齐 "Hackers or Hallucinators?" 的选型理由） |
| HTB Range | 真实基础设施 | 需 API 集成；分难度统计 |
| AutoPenBench | 自主渗透（33 任务） | 用于对标 21% / 64% 双基线 |
| PentestEval | 分阶段（346 任务） | 用于分阶段能力诊断 |

### 5.2 自建靶场

| 靶场 | 用途 | 关键要求 |
|---|---|---|
| **OWASP Juice Shop** | 隐私网关验证、基础 Web 能力 | 用于 Q5 红线（抓包零真实值） |
| **业务逻辑靶场**（M8 交付） | 业务逻辑检出率 | ≥10 类缺陷；**有/无 OpenAPI 双模式** |
| **内网多跳靶场** | 后渗透能力 | ≥3 跳；含 AD 环境；每跳有独立 ground truth |
| **反幻觉测试靶** | 幻觉率、归因准确率 | 预埋"诱饵"（随机哈希、类 flag 串、误判 banner） |

**反幻觉测试靶是一个特殊设计：** 它不是渗透目标，而是**陷阱**。预埋大量"看起来像成果但实际不是"的诱饵，专门用于测量 agent 是否会陷入 D1/D3。这是本项目独有的评测工具。

### 5.3 可复现性保障

| 项 | 措施 |
|---|---|
| 环境冻结 | 容器镜像按 digest 固定；依赖锁文件 |
| 随机性消除 | 固定随机种子；LLM temperature 记录并报告 |
| 时间快照 | 靶场版本、工具版本、模型版本全部记录 |
| 数据污染防护 | 优先使用 XBOW validation 与自建靶场（对齐行业选型理由） |
| 一键复跑 | `make bench BENCH=cybench` 完整复现 |
| 原始日志 | 完整轨迹归档，含全部工具调用与 LLM 交互 |

## 6. 报告结构

```
┌─ 1. 运行元信息 ────────────────────────────┐
│ 系统版本 / 模型与版本 / temperature / 种子   │
│ 靶场与版本 / 环境摘要 / 观测覆盖度           │
├─ 2. 主结果（仅 CONFIRMED）──────────────────┤
│ 检出数 / 误报数 / 漏报数 / 精确率 / 召回率    │
├─ 3. 新指标 ────────────────────────────────┤
│ 幻觉率 / 可复现率 / 越界尝试率 / 实体召回率   │
│ 每元漏洞成本 / 归因准确率                    │
├─ 4. 成本 ──────────────────────────────────┤
│ token 消耗 / 分级路由效果 / 单任务成本       │
├─ 5. 失败案例分析 ★ ────────────────────────┤
│ 每类失败归类 + 根因 + 改进方向               │
├─ 6. 能力边界声明 ──────────────────────────┤
│ 业务逻辑覆盖率（分有/无契约）                │
│ 后渗透能力边界 / 未覆盖场景清单              │
├─ 7. 附录（Candidate 级发现）────────────────┤
└────────────────────────────────────────────┘
```

**第 5 节（失败案例分析）的价值不低于第 2 节。** 报告不得只报成功——这既是诚实性要求，也是改进的主要输入。

## 8. 测试要求

| 类别 | 要求 |
|---|---|
| 可复现 | 同一环境连续跑 3 次，核心指标偏差 < 5%（LLM 非确定性下） |
| 第三方复跑 | 干净环境按文档操作可完整复现 |
| 靶场重置 | 每次评测后状态完全重置（污染检测） |
| 无手工填数 | 所有指标由脚本计算（静态检查：报告生成路径无字面量常数） |
| 诱饵有效性 | 反幻觉靶的诱饵能被 Agent 实际遇到（覆盖率验证） |
| 失败记录 | 失败任务必须结构化归档，不可丢弃 |

## 10. 风险与降级

| 风险 | 缓解 |
|---|---|
| 靶场维护成本高 | 优先用 Docker 化公开靶场；自建靶场只保留必要的三类 |
| LLM 非确定性导致结果波动 | 报告多次运行的中位数与分布，而非单次结果；固定种子 |
| 评测被质疑选样偏差 | 全部基准跑全量任务，不做筛选；公开失败案例 |
| 自建靶场代表性受质疑 | 与公开基准结果交叉验证；偏差 > 30% 时深究原因 |
| 复现成本高（算力/时间） | 提供分级评测（快速子集 / 全量）；CI 只跑快速子集 |

## 11. 诚实性承诺

M9 的价值不在于"跑出高分"，而在于**让分数可信**。三条承诺：

1. **不筛选**：全部任务、全部结果、全部失败，一并输出
2. **不混合**：白盒与黑盒、有契约与无契约、有人类提示与全自主，分开统计
3. **不隐藏**：能力边界与未覆盖场景显式声明在报告正文，而非附录脚注
