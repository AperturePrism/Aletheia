## 1. 职责

**让结论只能由证据显现，不能由模型声称。** 这是项目名 Aletheia（去蔽）的直接技术实现。

一句话：**M4 是系统里唯一有权说"这个发现了成立"的模块。**

---

## 2. 要解决的问题

调研记录的三个致命缺陷，全部由 M4 承担：

| 缺陷 | 实测表现 | M4 的对策 |
|---|---|---|
| **D1 幻觉式成功** | agent 报告"23/23 端口攻破、全部 root"，实际获 shell 数 = **0**。根因是验证器用字符串匹配（`searchsploit` 每次输出都含 "Shellcodes"，任何回显 "login:" 的服务都被判为已攻破）。修正为强制证据正则后，成功率从 23 掉到 3 —— **但这 3 个是真的** | 四道闸门 + 副作用观测强制化 |
| **D2 自言自语** | agent 停止真正执行命令，开始**想象命令输出**并在虚构结果上继续推理（EnIGMA 论文，ICML 2025） | G-1 执行绑定：无 `exec_id` 的输出视为虚构 |
| **D3 Flag 幻觉** | 发现一段 Base64 或随机哈希就断定是 flag，**幻觉成功后立即终止会话**。换更强模型也无法解决 | 终止仲裁：agent 无权自行终止 |

## 4. 内部设计

### 4.1 证据账本

```
Evidence Ledger（append-only，SQLite WAL / PostgreSQL）

ev_001 ──▶ ev_002 ──▶ ev_003 ──▶ ... ──▶ ev_N
  │           │           │                │
  └─ self_hash  ── prev_hash 链式校验 ────────┘

每条记录：
  exec_id（Sandbox 签名，不可伪造）
  tool（名称 + 版本 + argv + argv_hash）
  raw_output_ref（内容寻址 + 指纹）
  assertions[]（该证据支撑的断言）
  side_effects[]（目标侧副作用观测，每条隐含强证据）
  reproducibility（复现步骤 + 环境指纹）
  prev_hash / self_hash
```

**不可变性保证：**
- 接口层不提供 update / delete（只有 `Append`）
- `prev_hash` 链使任何中间修改可被检测
- 定期全链校验（每 N 条触发一次，发现断链即 P0 告警）

### 4.2 四道闸门

#### G-1 执行绑定

```
检查：Observation 是否携带有效 exec_id（Sandbox 签名验证通过）？
失败：判定为"自言自语" → 丢弃 + 幻觉计数 +1，不产生 Finding 记录
```

签名验证必须由 M4 独立完成（不信任调用方传入的 exec_id 字段）。

#### G-2 断言校验

```
检查：账本中是否存在支撑该断言的证据条目？
      · supporting_evidence_ids 非空
      · 每个 ID 在账本中真实存在
      · 证据的 tool/argv 与断言语境一致（上下文匹配）
失败：拒绝入库，降级为 HYPOTHESIS
```

#### G-3 证据强度

```
检查：是否存在目标侧副作用观测（SideEffectObservation）？
      · 强证据：ID_OUTPUT（uid=0 输出）、FILE_CREATED、ACCOUNT_CREATED、
                DATA_RETURNED（实际取回数据）、PROCESS_SPAWNED、CONFIG_CHANGED
      · 弱证据：仅工具输出自述（如 "exploit completed"）
规则：仅有弱证据 → 最高只能到 CANDIDATE
```

**证据模式必须可审计：** `matched_pattern` 记录命中的具体正则。参考实测中的正确做法：

```python
_SHELL_EVIDENCE = (
    re.compile(r"uid=\d+[a-z]+.*gid=\d+"),  # id(1) 输出
    re.compile(r"root@[\w.-]+:[~/]"),  # root 提示符
)


def breach_confirmed(output: str) -> bool:
    return any(p.search(output) for p in _SHELL_EVIDENCE)
```

**反面教材（必须避免）：** `if "login:" in output or "shellcodes" in output.lower(): return "confirmed"` —— 这条会产生 100% 假阳性。

#### G-4 独立复现

```
检查：在干净环境中按 reproducibility.steps 重放，是否复现？
      · 环境指纹匹配（镜像 + 网络 + 目标版本）
      · 复现结果与首次执行一致
失败：回退为 CANDIDATE，记录复现失败（复现失败率本身是核心指标）
```

**成本控制：** 仅对 CANDIDATE 执行（不对 HYPOTHESIS 浪费）；复现环境用容器快照复用。

### 4.3 状态机

```
HYPOTHESIS ──[G-2 通过]──▶ CANDIDATE ──[G-3 + G-4 通过]──▶ CONFIRMED
     │                          │                              │
     │ 任一闸门失败               │ 复现失败                      │ 归因冲突
     ▼                          ▼                              ▼
 REJECTED                  回退 CANDIDATE              → CANDIDATE + P0 告警
（记录原因供 Refiner）
```

**不可逆跃迁（除以下情形）：** `CONFIRMED → CANDIDATE` 仅允许由 `ATTRIBUTION_MISMATCH` 或人工复核触发，且必须记录触发者与理由。

### 4.4 归因双向校验（对 AIxCC Bundle 重罚机制的回应）

AIxCC 中错误关联扣 **7 分**（正确关联仅 +7，错误重罚）。本项目中它是 **P0 级缺陷**：

```
正向：finding.assertions[].supporting_evidence_ids  ──▶ 账本
反向：账本每条 evidence 的 assertions[]             ──▶ finding

双向一致的检查：
  ① 正向引用的证据必须真实存在
  ② 反向引用的断言必须属于同一目标实体
  ③ 证据的 target 与断言的 target_entity_id 必须一致   ← 关键：防止张冠李戴
```

**冲突处理：** 触发 `ATTRIBUTION_MISMATCH` → 回滚 finding 至 HYPOTHESIS + P0 告警 + 人工复核队列。

### 4.5 终止仲裁（Termination Arbiter）

**agent 无权自行终止会话。** 这是消除 D3（Flag 幻觉导致提前终止）的唯一有效手段。

```
agent 请求终止
      │
      ▼
┌─────────────────────────────────────────────┐
│ Arbiter 独立校验（不接受 agent 的自我评估）：  │
│  ① 达成物是否匹配目标定义？                   │
│     （目标是 flag？root shell？特定数据？）     │
│  ② 目标归属是否已确认？（在 scope 内、确属该资产）│
│  ③ 证据是否通过全部四道闸门？                  │
│  ④ 是否疑似幻觉？（随机哈希/Base64/误判 banner）│
└─────────────────────────────────────────────┘
      │
      ├─ 通过 → 批准终止
      └─ 拒绝 → 返回 guidance（避免 agent 陷入循环或反复重试）
```

**架构硬约束：** `RequestTermination` 是系统**唯一**的会话终止入口（除熔断）。任何直接 `return` / `sys.exit` / 关闭 session 的路径都是 P0 缺陷，CI 中有静态检查。

### 4.6 幻觉计数与熔断

```python
HallucinationState:
  per_agent_count: dict[agent_id, int]
  threshold: int = 3          # 单个 agent 累计 3 次即熔断
  session_total: int
  session_threshold_factor: float = 0.1   # 占总断言数 10% 即熔断整场
```

触发后动作：停止该 agent → 交 Refiner（M5）改写指令 → 若改写后仍触发则整个会话标记为"证据不可信"并在报告中显式声明。

## 6. 测试要求

| 类别 | 要求 | 门禁 |
|---|---|---|
| **伪造证据注入** | 三类用例 100% 被拒：① 无 exec_id ② 假 exec_id（签名无效） ③ 张冠李戴（证据 target 与断言 target 不一致） | **Q3（红线）** |
| 状态机覆盖 | 每条状态跃迁 + 每个拒绝分支都有测试 | Q1 |
| 归因冲突 | 构造错误归因 → 必须触发 MISMATCH + 回滚 + 告警 | **Q3** |
| 幻觉终止 | 50 组伪达成用例（随机哈希、Base64、误判 banner）100% 被拒 | Q1 |
| 假阴性 | 合法终止用例 100% 通过（防止仲裁过严） | Q1 |
| 账本完整性 | 篡改中间记录后全链校验必须检出 | Q1 |
| 不可变性 | 接口层无 update/delete 路径（静态检查） | Q1 |
| 副作用模式 | 证据模式库的正反例测试（含 `searchsploit` 头部含 "Shellcodes" 的经典反例） | Q1 |

**P0 门禁测试集是 M4 的核心资产**，应作为独立测试套件长期维护，任何修改契约或闸门逻辑都必须重跑。

**I2 结束时（P0 门禁）：**
- [ ] 伪造证据三类用例 100% 被拒

- [ ] 归因错误触发 P0 告警并可回滚

- [ ] 接口层确认无修改/删除路径

**I7 结束时：**
- [ ] 幻觉终止 0 次通过（50 组用例）

- [ ] 拒绝后 agent 能继续探索（循环检测有效）
- [ ] G-4 独立复现可运行，单次复现 < 10 min（超时则优化或降级为异步）

## 8. 风险与降级

| 风险 | 缓解 |
|---|---|
| 闸门过严导致漏报（假阴性） | 假阴性测试用例必须全绿；G-3 模式库可扩展；提供"仅记录不阻断"的 dry-run 模式用于调优 |
| G-4 复现成本过高 | 仅对 CANDIDATE 执行；容器快照复用；超时降级为异步 |
| Arbiter 被 agent 通过精心构造的证据欺骗 | Arbiter 不复用 agent 的推理，只做结构化校验；引入随机抽查人工复核 |
| 账本增长过快 | 按会话分区 + 冷归档；哈希链只保留摘要，原文走内容寻址 |
| 幻觉阈值设置不当 | 阈值外置配置；用真实运行数据校准；分 agent 类型设不同阈值 |
